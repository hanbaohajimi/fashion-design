# 服装秀工作区

Mode: Operate

Primary target: `src/modules/runway/RunwayWorkspace.tsx`

## 任务与视觉依据

服装设计师将已有款式修订或图片推进为需要人工核对的走秀视频。沿用现行 DESIGN.md 的暖白、深绿与工作室共享控件；这是已批准迁移方案中的工作室扩展，不建立新的视觉世界。

用户已经确定阶段式界面、完整流程、工作室内入口、旧模型适配、私有媒体和只读权限。按该明确任务直接实现；没有重新进行视觉方向选择。

## 层级与行为

- 对象名称、模拟模式和作品切换位于页面顶部；保存需求与开始制作是独立操作。
- 六个有序阶段用于查看成果，实际执行阶段另有“当前”标记；手动查看其他阶段时不会被后台进度强行切走。
- 人工配对、逐图核对和修改要求属于当前阶段，使用稳定媒体 ID 和中断 ID。修改失败保留输入。
- 模特与服装逐项配对，图片保持完整比例；视频保留原生播放、拖动进度和下载。
- 只读用户可查看和下载；离线执行器、停用功能、生成失败与远端结果不明确均显示具体状态。
- 历史运行与阶段重跑保留来源；项目复制提示服装秀资料和执行仍在原项目。
- 试衣、分镜和视频镜头可按单张建立重做分支；界面明确保留其他镜头与原有成果，媒体顺序依据持久化 ID 槽位。
- 本次运行的不可变需求快照与下一次运行草稿分开查看；引用预览使用实际母图，已保存快照优先于当前项目图片。
- 当前作品通过详情接口读取完整历史，旧作品和运行深链不会受列表预览数量限制；进度按运行版本单调合并，过期请求不会切走另一份草稿。

## 验证边界

`RunwayWorkspace.spec.tsx` 验证配对标识、幂等重试、修改冲突、只读、离线、绑定款式修订、停用及模拟来源。

`tests/e2e/runway-workspace.spec.ts` 使用真实 Next.js 页面和隔离 API fixture，验证深链、从款式进入、保存与执行分开、刷新、只读、键盘聚焦以及 1440/390 像素宽的溢出检查。

本轮最终定向验证：服装秀组件 22 条通过、项目卡回归 3 条通过、浏览器 4 条通过，Web TypeScript 和目标 ESLint 通过。独立终审提出的异步选择、版本倒退、旧深链、母图预览与历史需求快照问题已加入回归用例。终审最终结论由实施记录单独记录，不以测试通过替代审查。

独立审查者复核上述五项均为 resolved，结论为 `ship`，仅覆盖这五项修复；记录见 `output/runway-ui-review.md`。
