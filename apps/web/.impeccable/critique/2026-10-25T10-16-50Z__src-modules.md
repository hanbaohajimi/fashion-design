# Assessment A：当前生产 UI 独立设计审查

Method: independent design review A（/root/baseline_design_review）；未读取 Assessment B 或 detector 输出。2026-10-25，目标 `G:/new-fashion-design/apps/web/src`，运行页面 `http://127.0.0.1:3000`。

## 结论与设计特异性

当前工作台已经围绕服装作品组织：完整轮廓大图、作品旁“继续修改”、待发送引用与可切换流程画布，符合专业服装创作，不能笼统判断为通用后台。最值得重设计的是“从作品继续推进”的连续性：进入图片工具后，作品身份与款式交付入口退入菜单；进入 studio 后，素材变为图片序号或 ID，技术资料又成为独立长表单。用户需要自己建立这些界面之间的对象关系。

视觉系统整体克制、浅色、蓝色强调，基础一致性较好。登录的织物色片、印花平铺、样衣锚点和工作台作品组织有产品特征；不少交付模块的长表单与大片留白仍偏通用管理系统。优先改善对象身份、阶段推进与关键操作位置，比再增加装饰更有价值。

## 证据范围

本目录 73 张新截图，全部已逐张查看。覆盖 1440×900 / 390×844：首页、工作台、助手、助手菜单、设计要求、流程画布、全部 11 个 studio 模块、面料、趋势、登录、无效确认链接、有效/失效分享；另补 1366×768 当前工作台。主要浮层覆盖候选比较、未保存保护、图片工作区、图片菜单、局部重绘、版本历史、分享参数、单图导出、趋势存入项目与素材菜单。详见 `screenshots.md`。

使用当前真实 Next.js UI 和独立 Chromium 上下文，复用 `seedVisualApp`、`workspaceFixture`、`experimentFixture`。数据及图片均为隔离 fixture；SVG 只是布局样本，不评价真实服装图片质量，也不能把相同 SVG 造成的相似性当成产品缺陷。没有调用付费模型，没有写真实项目。导出队列状态为显式模拟。

基础审查测试 35/35 通过；扩展浮层和任务路径最终 4/4 通过。早期扩展脚本两项失败分别是缺少当前图片工作区 `/feedback` fixture、手机模块使用下拉框而非桌面 tab；已修正辅助脚本，非产品故障。最初素材菜单在入场动画开始时截图不可见，最终使用 `animations: disabled` 重拍；命中测试和真实点击均成功，不列为缺陷。全页截图中遮罩只覆盖视口是截图方式造成，不列为缺陷。

## 优点

1. 当前作品工作台让用户先看到完整服装轮廓，再继续修改。实测首页“继续创作”→作品“继续修改”→输入要求，只需两次点击和一次输入；待发送引用带名称，可核对讨论对象。证据：`workbench-1366.png`、`journey-reference-1440.png`。
2. 复杂能力已有渐进披露：studio 默认三项常用入口，其余按设计工具/开发交付/项目资料分组；技术包按章节；品牌规则和修订历史折叠。没有把 11 项功能无差别铺满首屏。证据：`studio-tasks-1440.png`、`studio-tech-1440.png`。
3. 确认与恢复的基础值得保留：未保存修改可继续编辑，图片历史说明恢复创建新版本，分享说明可见范围和七天有效期，导出明确离开后继续，实验失败项有独立重试。证据：`unsaved-1440.png`、`history-1440.png`、`share-panel-390.png`、`tech-export-queued-1440.png`、`studio-experiments-1440.png`。

## 五项高价值问题

### P2 — 图片工作区将“当前是谁、下一步交付什么”藏入图像菜单

**实测**：打开工作台方案后进入全屏图片工具。默认顶部只有“图像”、缩放、下载、分享、关闭；作品名、版本历史、来源与设计决策、保存为款式都在“图像”菜单内。底部却直接展示七种编辑工具。用户完成生成后的关键下一步“选为款式”比次要图像加工更难发现。

**证据**：`candidate-detail-1440.png`、`image-menu-1440.png`、`candidate-detail-390.png`。来源：`apps/web/src/modules/board/workflow/WorkflowAssetWorkspace.tsx`（标题与保存款式均在 menu 条件内部）。

**建议**：常驻显示作品名、修订/来源摘要；将“继续修改 / 比较选款”置于当前作品动作区。标注与图像处理仍保留，但分组折叠。与工作台共享对象栏，避免用户进入图片工具后失去项目语境。建议命令：`$impeccable shape`、`$impeccable clarify`。

### P2 — studio 素材身份退化为序号或 ID，要求用户靠图像记忆跨模块匹配

**实测**：款式主图和比较选择器显示“图片 1/2/3”；实验母图为“图片 1 · et-front”；样衣关联照片直接显示 `asset-front`。这不是 fixture 缺名字的单纯显示问题：共享素材选择器源码按 index 固定输出“图片 n”，部分模块直接截取 ID。

**证据**：`studio-styles-1440.png`、`comparison-1440.png`、`studio-experiments-1440.png`、`studio-samples-1440.png`。来源：`apps/web/src/modules/studio/studio-ui.tsx:63`、`:86`，`PrintWorkbench.tsx:229`，`CollaborationPanel.tsx:551`。

**影响判断**：相近候选增多时，用户需要记住哪张图属于哪一轮/哪次修改。这里未实际测量选错率，也不声称 API 丢失引用。

**建议**：用稳定的作品名称、视图类型、生成轮次/修订配合缩略图；ID 只放详情。跨模块保留同一对象条与来源入口。建议命令：`$impeccable clarify`、`$impeccable shape`。

### P2 — 比较界面重复呈现图库，把比较结论和采用动作推到首屏之外

**实测**：选中两张后，候选选择器仍在顶部占据大块高度，下方再重复展示两张大图。1440×900 中只到“方案 1/2”，采用理由与采用动作低于模态可视区；390 下连完整候选选择列表也需滚动。它能完成比较，但视觉空间首先服务“选了哪几张”，没有优先服务“为什么选这张”。

**证据**：`comparison-selected-1440.png`、`comparison-390.png`。来源：`apps/web/src/modules/studio/StyleLibrary.tsx`。

**建议**：选完后将选择器收成可展开缩略条；比较区保留同尺寸完整图、名称/来源与少量比较维度；采用理由和当前采用动作固定在比较区下沿。手机使用两张并置缩略图/可切换大图，始终保留另一方案名称和差异记录。建议命令：`$impeccable distill`、`$impeccable layout`。

### P2 — 手机仍按桌面长表单顺序堆叠，常用复核动作与图片相距过远

**实测**：390 宽度的样衣页需先经过页面导航、轮次资料、技术包、上传和照片折叠，再看到问题图与问题描述；团队页把评审文本与批准按钮放在大图之后；款式档案修改保存位于约两屏之后。当前图片工具栏首屏仅露出标注/评论/移除背景/擦除，局部重绘和变体需要横向滚动。并非“无法操作”，而是手机查看/沟通/关键操作的优先级没有单独表达。

**证据**：`studio-samples-390.png`、`studio-team-390.png`、`studio-styles-390.png`、`candidate-detail-390.png`、`inpaint-390.png`。

**建议**：手机先显示当前作品与待处理事项，资料编辑折叠到次级面板；固定当前动作栏并留出底部遮挡安全区；图片工具按“修改 / 标注 / 更多”分组。建议命令：`$impeccable adapt`、`$impeccable distill`。

### P2 — 技术包发布前只有分散复核输入，没有“还差什么”的完成概览

**实测**：基本资料页仅有款式修订下拉框，占一个大内容面板；七个章节均同权显示。切到复核发布后展示交接说明、总复核勾选和规则文本，没有汇总哪些视图/BOM/POM/配色尚未复核。当前 fixture 中 BOM、POM、配色未复核，用户必须逐章查看才能确定剩余工作。

**证据**：`studio-tech-1440.png`、`tech-bom-1440.png`、`tech-review-1440.png`。来源：`apps/web/src/modules/studio/TechPackEditor.tsx`。

**建议**：基本资料成为当前款式预览与交付摘要；章节显示待完成计数；发布前列出具体缺项并一键定位字段。保留人工确认与修订绑定，不简化成自动批准。建议命令：`$impeccable clarify`、`$impeccable onboard`。

## 认知负载

按规则逐项判断（跨主任务整体）：单一焦点通过；视觉分组通过；视觉层级通过但比较页较弱；渐进披露通过；分块失败（图片工具七项、技术章节七项）；最少选择失败；一次一个决定局部失败（比较时同时选图、读重复图和向下找结论）；工作记忆失败（序号/ID、跨模块对象身份）。整体 **4 项失败，高负载**，主要集中在比较与交付转换，不应概括为整个首页或当前作品工作台都过载。

已验证 >4 可见选项的决策点：图片底栏 7 种工具；图像菜单 5 项动作；添加素材菜单 7 类；技术包 7 个章节。专业工作不应机械压到 4 项，但应区分当前阶段主动作与可选工具。studio 折叠导航是已有正例。

## 情绪路径与角色风险

开场峰值是工作台大图和直接继续修改；查看作品时有创作感。谷值出现在从作品进入全屏工具再找“保存为款式”，以及从比较切入长表单。交付末尾“排队中，离开后继续”提供安心感；失效分享页只有“分享不存在、已过期或已撤销”，缺少请求新链接等可执行下一步，削弱最终交付体验。

- **Alex / 专业设计师**：跨作品、实验、款式、技术包不断重新识别对象；比较首屏没到采用理由。优先验证三种原型是否减少这些跳转和记忆桥。
- **Jordan / 首次协作评审者**：图片工作区“图像”菜单不预告里面有“保存为款式”；技术包七章缺少待完成导航。无需新增大段说明，应让下一步可见。
- **Casey / 手机快速评审者**：全页资料先于当前批注和批准；大图后才是评审输入。优先支持查看、批注、确认，再展开完整编辑。

不对 Sam 的读屏/键盘可达性作完整结论：本次仅实测部分 Escape、点击与原生表单，没有跑完整键盘/读屏路径，也未做对比度量测。

## 次要观察与待验证

- 失效分享缺少下一步，证据 `share-expired-390.png`；可补“请向分享者索取新链接”，网络失败另提供重试，不需要泄露私有项目信息。
- 手机图片工具顶部“图像”“分享”拆成两行，见 `candidate-detail-390.png`；可用紧凑图标配可访问标签减少拥挤。
- 登录与无效确认的下一步明确。登录手机上品牌插图先于表单，约占上半屏；优先级低于创作链路。
- 首页与趋势封面裁切样本图。不能据此评价真实趋势图片，但未来应核查服装轮廓展示政策与封面裁切策略。
- 没有覆盖面料详情/上传、完整创建项目、全部工具参数、草图编辑、真实成功确认链接、全部权限角色、长文本与错误边界；基础截图不是这些状态的证据。

## 用于三个原型的比较问题

1. 能否让“作品 → 比较 → 款式 → 交付”持续显示同一个对象身份，而无需用户回忆图片序号？
2. 一个已有作品的设计师打开页面后，能否在不滚动、不理解流程节点的前提下完成下一次修改入口选择？
3. 手机评审能否只保留“看图、留意见、确认”这条短路径，并仍能追查修订来源？

Questions skipped: 这是交给父代理综合的独立 Assessment A，用户已要求先比较三个交互方向，此处不另向用户索取确认。
