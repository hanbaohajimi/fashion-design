# 已批准的实施计划

## 产品边界

当前项目的“商品展示”增加“衣架搭配”，与“展示包”和“实时试穿”并列。工作台图片和款式档案有“加入衣架”入口，入口只打开素材准备，不自动确认单品或调用模型。原有单件实时入口和展示包不改变含义。

单品涵盖上衣、外套、裤裙、连体服、鞋、包、帽、围巾、腰带和其他配饰。设计源图始终保留；允许显式生成提取或补全候选，但只有逐项核对并确认的版本才能进入衣架与试穿。挂具是独立展示层，不进入模型参考图。

衣架使用透明图片、独立挂具与受控透视；侧挂、悬停转正、邻近让位、连续切换、聚焦和返回均按视频对照实施，不声称三维服装或物理布料模拟。浏览和动画不触发生成。

同一份完整搭配快照用于模特 AI 试穿及本人摄像头试穿。默认按部位和层次替换，明确叠穿可保留多件并调整顺序。模特试穿始终手动更新；本人模式只有启动后明确修改搭配才更新完整输入。返回本人模式不自动启用摄像头。

本次不包含系列管理、跨项目衣橱、商城交易、真实三维建模或新的摄像头会话实现。

## 实施顺序

1. 保存既有差异并核对摄像头任务交付；建立视频逐项对照。先验证衣架表现和组合参考图，不将拼图等同模型可用。
2. 建立项目内单品、单品不可变版本、搭配和不可变快照。权限、来源及幂等由服务端校验。
3. 建立选择来源、指定类别与目标、准备素材、原图候选并排核对、设置挂点、确认入架流程。失败和重做保留原图。
4. 实现视频衣架行为、跨类别展示、筛选搜索分组、独立加入按钮、替换／叠穿／排序／移除及撤销。
5. 连接现有 GenerationService 和摄像头控制器。使用原始模特与快照，结果绑定固定来源；串行完整实时更新，合并未执行项，截图绑定已应用快照。
6. 接入本机草稿、结果保存与工作台；执行静态检查、单元／集成／浏览器测试和视觉对照；真实供应商效果单独验收。

## 保留约束

- 本轮开始的 Git 差异保存于 `output/wardrobe-tryon/baseline/`。不覆盖其他任务修改，不提交、推送或部署。
- 摄像头界面任务结束后追加兼容；保留会话预算、断连、停止、资源释放和截图机制。
- 默认不调用付费模型。供应商配置或真实效果未验收时保持对应能力关闭，不用演示图片或单上衣结果替代多件验收。
- 原始服装主体完整显示，不拉伸、调色、裁切；无背面依据时不产生镜像或假背面。
- 文档在本目录；手工工具在 `scripts/manual/`；所有生成输出在忽略的 `output/`。
