# 接口、配置与迁移

## 入口与组成

`/{projectId}/studio?tab=presentation&mode=wardrobe` 打开衣架；附带 `assetId` 可进入单品准备，附带 `styleRevisionId` 可明确来源修订。原 `mode=realtime`、展示包、款式资产深链保持兼容。

- `apps/web/src/modules/studio/wardrobe/`：单品准备、陈列与聚焦、搭配编辑、模型／本人试穿、来源和任务反馈。
- `apps/api/src/modules/wardrobe/`：项目权限、素材准备和确认、快照、真实参考图合成、模型任务业务入口。
- `packages/shared/src/wardrobe.ts`：输入校验和共享视图契约。
- `apps/web/src/modules/studio/realtime-tryon/` 与 API 对应模块：在原摄像头交付基础上兼容完整搭配，不替换原预算、SDK、断连或释放机制。

## 项目接口

以下路径均以 `/projects/:projectId/wardrobe` 为前缀。读操作要求项目访问权；写操作要求编辑权、项目未归档及相应功能开关。所有引用均校验当前项目归属，不能利用另一个项目的资产 ID 绕过权限。

| 方法与路径 | 作用 |
| --- | --- |
| GET `/` | 单品、准备任务、搭配快照、试穿记录及能力 |
| GET `/assets/:assetId/bounds` | 权限校验后的真实透明主体像素范围；供候选与历史单品按实际服装尺寸陈列，不创建任务 |
| POST `/prepare` | `sourceAssetId`、类别、来源类型、处理方式、参考图与可选框选；返回准备记录／候选，不发布 |
| POST `/confirm` | 确认候选、类别、挂具、挂点和 `reviewed:true`；可带 `itemId`、`expectedVersion` 新增单品修订 |
| PATCH `/items/:id` | 收起／恢复单品；带版本号和请求键 |
| PATCH `/items/:id/presentation` | 核对侧挂候选、挂点与挂具宽度后创建展示修订；正面试穿资产保持不变 |
| POST `/outfits` | 保存所选固定单品修订、层次、穿着说明；修改时要求预期版本 |
| POST `/snapshots` | 从当前草稿生成临时试穿快照；不进入正式搭配列表；可用 `baseSnapshotId` 验证原有归档引用 |
| GET `/snapshots/:id` | 读取固定搭配快照并校验素材可用性 |
| POST `/snapshots/:id/reference` | 在服务端生成真实 PNG 并登记私有资产和全部来源；不是返回一个未生成的 URL |
| POST `/tryon` | `snapshotId`、`modelAssetId`、`requestKey`，返回现有生成任务关联记录 |

幂等请求键在项目、用户范围内绑定输入指纹。相同请求重试复用结果；同键不同输入拒绝。版本冲突返回明确错误，不能覆盖其他标签页的修改。

## 数据与素材

单品身份与单品修订分离；搭配身份与快照分离。版本保留源资产、确认资产、可选款式修订、类别、挂具、挂点、来源类型和生成补全标识。快照固定完整单品修订及层次，更新单品素材或搭配不会改写旧快照。

对已生成候选再次提取或复用时，`sourceKind` 仍表示本次输入，`generatedCompletion` 则沿同项目资产父链和历史准备／确认记录保留祖先补全事实；尚未确认的生成候选同样适用。循环、过长或跨项目来源链不能被默认为原生素材。资产的 `parentAssetId`／`rootAssetId` 保留到原设计的递归血缘，不因后续去背景、裁取或素材修正而抹去生成来源。

质感返工增加可选 `imageBounds`（原图像素及 alpha 主体边界），确认时写入既有修订 JSON；旧版本按需通过只读接口补齐，不要求新增迁移。具体字段、权限、缓存及真实照片验证见 [REALISM.md](REALISM.md)。

真实生图验证增加可选 `presentation`：`supportWidthRatio` 表示挂具相对正面可见主体宽度，`shelfDepthRatio` 表示托面后向纵深相对托架宽度（范围 `0.08–0.5`，省略沿用品类默认值），`sideDisplay` 保存独立侧挂素材、原始像素范围、挂点、方向、准备记录、生成／上传来源及核对状态。托面为单一透视平面，前后支点不强求相同屏幕 y 坐标。单张正面图的透视压缩不能产生真实侧缝和袖筒，因此已确认的侧挂图用于静置陈列，悬停转回确认正面；没有侧挂图的历史修订继续兼容原透视陈列，但不能据此认定侧挂真实感已经验收。

显式准备侧挂时使用既有 `POST /prepare`，附加 `presentation:{view:"side",revisionId,orientation:"left"|"right"}`。生成必须以对应修订的确认正面为 `sourceAssetId`，`sourceKind:"isolated"`、`mode:"complete"`；上传已有侧挂图使用 `mode:"existing"`，须为独立透明素材。禁止将侧挂候选通过普通 `/confirm` 当作试穿正面。

修正已完成的侧挂候选时，在 `presentation` 中增加 `repairPreparationId`，`sourceAssetId` 指向该准备记录的真实候选，使用 `sourceKind:"isolated"`、`mode:"extract"`，不带框选和额外参考。服务端验证原准备记录属于同一项目、单品修订、方向及类别，且候选仍可访问；未完成任务、普通正面准备及跨项目引用均拒绝。修正保留侧视角度，不再次生成侧转，返回新的任务和候选。修正结果只能经过同样核对后采用为侧挂图，父资产及原始设计链保持可追溯。

`PATCH /items/:id/presentation` 接收 `requestKey`、`expectedVersion`、`revisionId`、可选 `frontAnchor`、`supportWidthRatio` 与 `shelfDepthRatio`，以及可选 `sideDisplay:{preparationId,assetId,anchor,reviewed:true}`。省略侧图保留原值，传 `null` 明确移除；省略深度同样保留已有校准。正面挂点、托面纵深和宽度校准只改变展示元数据，不需要重新生成服装，也不会丢失已确认侧图。服务端检查项目、候选完成状态、实际透明度、来源修订、最新版本和编辑权限，再创建不可变修订；旧搭配继续引用旧版本。试穿、参考图合成始终引用修订的正面 `assetId`，不会使用侧图或把挂具烘焙到素材里。本次展示信息仍写入既有 JSON，无新增数据库迁移。

本人连续试穿使用 `isTrial` 标记的临时搭配记录来承载快照，它不进入正式搭配列表，也不清除本机未保存状态。明确编辑后串行准备最新完整快照和参考图；准备期间保留已应用的画面、暂停截图，成功后更新原会话。正式“保存搭配”仍是独立操作。

已有透明单品经过服务端实际读取、格式及透明度检查，再进入人工核对；该检查不能判断服装语义完整性。AI 提取／补全候选走现有图像生成、队列和资产链路，仍必须人工核对。框选只缩小目标范围，不代表自动恢复遮挡细节。

浅色蕾丝／网纱补充显式的透明材质修复。`POST /material-alpha/probe` 接收 `requestKey`、`sourceAssetId`、`maskAssetId`、可选原图 `detailRegion`、名称、类别和说明；只有这一操作提交收费 INPAINT 任务。第一图始终是完整原图，第二图按选区原像素裁取，蒙版登记为同项目私有资产。选择区域须同尺寸、有明确编辑区及保护区、PNG 小于 4 MB，原图最多 4,194,304 像素且已有有效外部透明背景。绿色织物选区不适用该固定算法。

选区上传复用已有 `generations/masks/sign` 的校验和签名与原始 PNG 上传。`POST /material-alpha/mask` 再接收 `requestKey`、`sourceAssetId`、`maskId` 和十六进制 SHA256，仅从当前用户的临时掩码命名空间读取，核对实际字节、尺寸及选区后复制为永久私有资产。该分支不经过普通 FileAsset 缩略图及视觉摘要队列，不额外触发模型分析。永久对象与签名上传临时对象使用不同路径，后续临时覆盖或清理不改变已保存蒙版。默认款式素材列表与数量排除内部选区、细节裁片及透明处理中间图，来源详情仍能按权限访问它们。

`POST /material-alpha` 接收已成功中间结果的 `rawAssetId` 及原图、蒙版、名称、类别和请求键。它验证真实 INPAINT 的父资产与冻结首参考、蒙版对应关系，执行确定性 alpha 派生并保留全部原图 RGB 和保护区 RGBA；不会再请求供应商。派生图经新 `existing` 准备记录进入三底人工核对，不能自动入架。`materialProcessing` 在准备记录和确认修订中暴露算法、三来源及 SHA，原图、模型原始中间图、蒙版和派生图分别保留。生成成功但派生失败时仅重试不收费的派生步骤。中间图不能直接当作已确认服装；这一补充仍不代表任意半透明材料或新的侧挂视图通过。

侧挂候选的透明修复复用上述流程，在派生请求中额外传入 `sidePreparationId`。服务端核对原侧挂准备、候选资产、类别、项目与冻结正面修订，派生结果继续保留原侧挂方向和修订，不会成为可直接确认的正面单品。保存侧挂时再次检查当前单品版本；旧修订的派生记录可以保留和幂等重放，但不能覆盖更新后的展示。侧挂修订单独保存 `materialProcessing`，正面试穿素材不变。

同一套蒙版登记、生成和派生接口还支持显式 `operation: "correction"` 的局部细节修正；省略该字段保持原透明修复兼容。该模式必须填写修正说明，生成提示不使用绿色孔隙。新派生使用 `masked-provider-rgb-interior-v2`：只有原图 alpha 至少 240、且以该像素为中心的 5×5 邻域均满足该条件的内部像素，才按蒙版权重采纳真实模型 RGB；其余 RGB、整图 alpha 和选区外 RGBA 保持原样。固定 2 像素内缩防止模型背景混入原图抗锯齿边缘，阈值、半径和实际保护统计随处理记录保留。选区没有可编辑内部像素时，在付费任务创建前拒绝。

旧 `masked-provider-rgb-preserve-alpha-v1` 算法和历史 metadata 保留，相同请求键重放返回既有派生结果，不静默升级或改写旧素材。使用新版处理同一真实模型结果必须新建请求键和候选，无须再次调用模型。局部 RGB 修正不能扩大轮廓、延长裤腿、改动薄纱透射或替代真实三维结构；内部细节是否正确仍需人工核对。

局部修正仍要求同尺寸、真实透明来源和对应成功 INPAINT；派生时核对任务处理模式，不能把透明中间结果混用为颜色修正。结果标记为 `materialProcessing.kind: "masked-edit"`，保留三来源、四份 SHA、独立原始模型结果和待核对准备记录。正面和侧挂分别提供显式入口；重试无收费的派生步骤不重新生成。侧挂仍绑定原修订并再次人工确认，不能自动替换原正面或历史搭配。

局部修正画笔提供向选区内渐变的柔和边缘，预览与导出使用相同权重。每笔保存当时的笔宽与柔和程度，后续调整设置不重绘旧笔画；原透明修复与工作台蒙版的默认边缘保持兼容。柔化可以缓和局部 RGB 的衔接，但不能自动修复大幅曝光或织纹差异，仍要核对实际派生候选。

局部细节修正还会自动生成同源选区的位置参考：第一图仍是完整原始单品，第二图仅将有效内部选区按实际蒙版权重叠加 45% 品红，可选的同源原像素细节排在第三图。位置参考保持画布、构图与 alpha，不推断中心线、不新增服装结构，也不能作为单品确认；原蒙版仍单独传给供应商。参考单独存为私有派生资产，保留原图／蒙版和处理摘要，普通素材列表不显示它。提示明确禁止将标记颜色复制进成衣；模型是否准确落点仍须逐图核对。历史请求重放沿用原任务与冻结引用，不因新增参考而改写既有任务或重复收费。

参考图由确认图片按完整比例放入干净画布。新参考采用 `body-regions-v1`：从上到下分为头颈、上身、连体服装、腰腿、鞋履和携带物／其他配饰，各组内按层次顺序独立展示。内搭和外套互不遮挡，未知配饰不推断具体佩戴部位；长款仍完整等比显示，不画文字或将服装合成为人体。组别和顺序来源于冻结快照中的类别与层次，处理记录保存布局版本及全部单品修订；已经生成的历史快照参考图不改写。挂具、标签、UI 和模型人物不进入该参考图；不会以拼图成功推断真实多件试穿成功。原始模特单独作为静态生成的首张参考，后续参考为全部选定单品。

模特试穿使用显式业务上下文和冻结输入，复用 GenerationService、计费、取消及结果资产，不启动服装秀。任务记录指向原始模特与固定快照；迟到结果保留在其自身版本。新任务失败不清空旧结果。

实时模式继续使用 `garmentRevision` 表示会话应用序号；`outfitSnapshotId` 表示业务快照，二者不可混用。完整描述从当前单品及层次重新编译，不使用静态多参考图片序号提示。更新串行、合并等待项，旧快照画面不标记为新搭配截图。关闭模式或离开项目继续停止和释放原控制器资源。

## 增量升级

1. 保留现有 `.env`，按 `.env.example` 追加本次开关；不改变已配置的摄像头预算和来源允许列表。
2. 安装锁定依赖：`pnpm install --frozen-lockfile`。
3. 运行 `pnpm db:generate`、`pnpm db:deploy`。新增迁移为 `packages/db/prisma/migrations/20261030010000_wardrobe/` 和 `20261030011000_wardrobe_trial_snapshots/`，须在此前摄像头迁移之后依次应用；不改写已应用迁移。
4. 运行相关检查并构建：`pnpm build`，按现有本地启动方式重启应用和 worker。
5. 按独立验收结果逐项开启功能。新增收费入口默认关闭；衣架资料编辑可独立使用。多件实时试穿必须同时满足实时配置、类别允许列表与多件验证开关。

| 配置 | 含义 |
| --- | --- |
| `WARDROBE_ENABLED` | 衣架编辑能力开关 |
| `WARDROBE_PREPARATION_ENABLED` | AI 素材提取／补全入口 |
| `WARDROBE_STATIC_TRYON_ENABLED` | 模特生成入口 |
| `WARDROBE_REALTIME_OUTFIT_ENABLED` | 搭配实时输入兼容入口 |
| `WARDROBE_REALTIME_MULTI_ITEM_VERIFIED` | 多件组合已经真实验收后才可开启 |
| `WARDROBE_REALTIME_CATEGORIES` | 已验收可用类别，逗号分隔；不能以“top”替代整套搭配 |

实际默认值及服务端校验以 `.env.example` 和 `wardrobe.rules.ts` 为准。图像供应商使用既有 GenerationService 配置；实时供应商仍使用[摄像头接入配置](../realtime-tryon-api/IMPLEMENTATION.md)。
