# 画布与助手主流程精简

本轮承接首页与工作室精简，集中处理设计画布和右侧助手。采用 refactoring-ui 的层级、单一主操作与去重原则，延续 Figma 式的画布与上下文面板分工：画布承载素材和设计路径，助手负责输入、确认与查看本次结果。

## 流程变化

原流程：添加需求节点 → 输入需求 → 预览提案 → 加入画布 → 找到工具并打开详情 → 确认执行 → 在画布寻找结果。

新流程：描述需求 → 查看并确认方案 → 在对话中打开结果。确认会连续完成保存和执行，画布同步保留素材、节点与来源关系。新项目若需先分析需求，仍会出现明确的“确认并分析”，不因精简而自动跳过分析或启动付费生成。

## 删除与合并决策

| 原设计 | 处理 | 原因 |
|---|---|---|
| 提案的“加入画布”和详情的“确认执行”分两次操作 | 合并为“确认并生成 / 确认并分析” | 已经确认同一方案，无需再次寻找执行入口 |
| 助手内另一套参数、输入绑定、调整原因表单 | 删除，修改要求复用原对话输入框 | 减少两套输入机制；保留原提案关联与明确引用 |
| 工作计划面板及独立轮询 | 删除前端展示与请求 | 与对话、画布和执行状态重复，不再让用户先理解里程碑 |
| 跳过理由表单与第二次跳过确认 | 删除，改为一次跳过 | 跳过不会执行生成；旧记录的跳过理由仍可阅读 |
| 自动套用选中素材的两条建议按钮 | 删除 | 选中素材不代表用户想执行某个任务，保留显式引用 |
| 空画布“添加设计需求”弹窗起点 | 改为“开始设计”，直接聚焦助手 | 不要求首次使用者理解节点建模 |
| 结果只能从画布进入 | 与提案卡片合并，显示本次结果缩略图 | 原位打开既有候选资产工作台 |
| 两层用户消息气泡 | 删除内层背景、缩进与额外留白 | 降低手机滚动负担，让确认操作和结果更易看到 |

保留独立职责：节点详情仍用于精确参数编辑；画布连线、草图、图片、版本、设计上下文与历史会话仍可使用。未删除后端业务模块或已有项目数据。以上删除是前端代码和交互的删除，而非把旧表单藏进折叠菜单。

## 设计审查

| 严重度 | 位置 | 规则 | 问题与修正 |
|---|---|---|---|
| P1 | 空画布 | §2.1、§2.8 | 缺少明确下一步；起点直接连接需求输入 |
| P1 | 方案确认 | §2.4、§2.8 | 确认与执行脱节；仅一个主操作并明确生成数量、保留项及计费提示 |
| P1 | 方案修改 | §2.1、§3.6 | 重复参数表与对话竞争；统一为同一输入框 |
| P1 | 助手状态 | §2.4 | 计划、提案、回执并行呈现；移除计划 UI，用提案卡反映执行和结果 |
| P2 | 手机对话 | §3.6 | 消息嵌套留白过多；合并气泡，结果到达时遵守跟随阅读状态 |

沿用现有浅色设计令牌、字体和控件，无新增依赖。桌面按 1280px、手机按 375px 检查确认卡、空态与结果；窄屏保留输入框和可滚动对话。查看历史时新结果不会强制滚动，只提示有新消息。

## 执行与恢复

- 接受成功才提交执行；接受失败不会启动生成。
- 使用稳定请求标识，连续点击和提交响应丢失后的恢复复用同一执行请求。
- 已保存但未提交成功时显示“继续生成”；已运行或已完成时不重复执行。
- 实际执行失败后才允许新的明确重试。
- 数量、尺寸、保留要求和明确参考在确认前展示；对话输入和“修改要求”本身不会执行生成。
