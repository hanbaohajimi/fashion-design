# 系统可靠性优化

日期：2026-10-28。起始提交：`f6434b5`，开始时工作区干净。本轮聚焦实际故障和创作内容保护，沿用现有界面、业务权限、人工确认与计费规则。

## 行为改进

| 范围 | 问题与修复 |
| --- | --- |
| 本机草稿与账号 | 公开分享页、登录页和确认页的临时空会话不再被当成退出账号。确认退出、会话失效或换号时才清理对应账号，保留其他账号草图。退出请求合并执行，旧会话响应失效；退出失败后重新核实身份，避免丢失另一标签的换号通知。 |
| 画布保存 | 切换项目或卸载后隔离旧加载、保存和重试回调。保存期间的新修改及时写入恢复记录并推进基线；浏览器存储清理失败不重复提交已成功保存的数据。 |
| 浏览器后退 | Chromium 中保存快速完成时，原生后退会在被取消的导航事件结束前重放并报 `Invalid key`。重放改为下一浏览器任务，确认原页面仍有效，同时处理提交与完成两个 Promise；保存失败继续停留，离开后的迟到重放被忽略。 |
| 任务中心 | 统一同时间戳分页的排序和游标比较，规范化游标时区并拒绝非法结构。展示稿、技术包及图片导出按真实来源定位，保留修订或素材关联。 |
| 轮询查询 | 七类任务只读取展示和操作所需字段，避免读取完整助手正文、提示词及运行快照；关联查询并行执行，无关联时跳过。未进行生产负载基准，不宣称固定性能提升比例。 |
| 导出回收 | 旧清理消息只处理绑定的旧对象；排队、运行和失败待重试的导出不会被标为过期。存储删除成功后按对象、状态和期限条件更新，避免覆盖重试产生的新结果。 |
| 生成后续分析 | 已提交的图片、计费和生成成功状态不受辅助分析查询或投递失败影响。批量投递等待全部结果，只标记本次明确投递失败且仍待分析的图片，保留其他任务及运行中、已完成的分析。 |
| 隔离验收启动 | `run-trial-e2e.mjs --checks` 不再把试用应用的 `NODE_ENV=development` 传入质量检查。Vitest 与 Next 构建各自选择测试和生产模式，避免测试 fixture 意外启动后台消费者争用待处理事件。 |

## 依赖整理

移除 API 未使用的开发依赖 `@nestjs/cli`，同时移除其独占的 92 个传递包，包括 `deepmerge@4.3.1`。现行 API 构建、开发、检查分别使用 `tsc`、`tsx` 与已有 pnpm 脚本；运行时 NestJS 保留。锁文件仅删除相关条目，没有升级其他依赖。

处理依据：[GHSA-gcqx-w48m-w2h4](https://github.com/advisories/GHSA-gcqx-w48m-w2h4) 公告与[未合并的上游修复](https://github.com/TehShrike/deepmerge/pull/274)。本轮没有增加审计豁免，也没有降低审计失败规则。

首轮组合 `pnpm check` 暴露闲置 CLI 带入的依赖公告；移除后在线审计独立运行成功，但组合命令再次遇到原有 60 秒网络超时，仍按原规则失败。随后在同一隔离启动流程中逐项执行其余检查，没有放宽审计、跳过业务断言或将组合命令记为一次性通过。临时续跑入口与原始日志均保留于忽略的 `output/`。

首次应用测试因试用环境的 `NODE_ENV=development` 泄漏出现 3 项失败，修复启动器后完整重跑全部通过。真实应用测试还更新了两处已过时的原生 `selectOption` 操作，复用现有选择控件助手点击真实按钮及选项，未拦截平台接口或删除断言。

3 项条件跳过分别要求 `RUNWAY_PIPELINE_INTEGRATION`、`ASSISTANT_PROXY_ORIGIN` 和 `IMAGE_WORKSPACE_LIVE`；本轮未启用这些额外环境，也未执行全量视觉截图比较。

## 升级与边界

运行 `pnpm install --frozen-lockfile` 同步依赖，重新构建并重启 Web、API 与 Worker。本轮无数据库 schema、迁移或环境变量变更，不调用付费模型。

旧画布保存请求在离开后若结果未知，保留已有恢复记录，重新打开时仍使用现有版本冲突处理。浏览器清除站点数据或本机存储不可用时，草稿恢复能力受原有边界限制。

测试使用真实 PostgreSQL、Redis、MinIO 和认证的隔离环境，外部 AI 使用本地确定性替身；浏览器契约测试使用平台 API fixture。二者不替代真实模型质量验收。
