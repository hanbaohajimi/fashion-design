# 设计工作台与过程合并

## 本轮判断

原画布将需求、分析工具、设计约束、生成工具、候选、评估工具和评估报告作为平级节点排列。用户需要读懂处理流程，才能找到服装图。仅把工具节点缩小，仍会保留连线和中间步骤带来的阅读负担。

本轮默认使用按作品组织的设计工作台，完整流程画布作为独立视图保留。工作台没有工具端口、类型编码或流程箭头，用户直接查看服装、打开详情、引用素材或继续修改。

技术基础保持 Next.js App Router、React、CSS Modules、自建共享控件与既有浅色设计令牌；流程编辑继续使用 tldraw。没有新增依赖，没有改动数据库和执行契约。

## 合并与保留

| 对象 | 工作台中的处理 | 保留的职责 |
|---|---|---|
| 同一次生成的多个候选 | 合并为一个方案组，服装图片并排显示 | 每个候选仍可独立打开、修改、查看版本 |
| 需求分析、设计约束 | 过程不再独立占据画面；约束归入对应方案的设计说明 | 保留真实要求与完整来源记录 |
| 评估工具、评估报告 | 合并进对应方案的设计说明，按实际候选过滤摘要 | 完整评估仍可打开，不混入其他修改分支 |
| 多段输入、输出连线 | 转为方案旁“参考了”的素材标签 | 标签可打开真实来源；修改方案只追溯到直接母图边界 |
| 需求文本 | 合并到设计方向区域 | 多份已有需求均可访问和编辑 |
| 图片、面料、文字、色卡 | 独立参考素材区，可直接引用到助手 | 保留上传、来源与原始图像比例 |
| 失败、进行中和未执行步骤 | 显示为精简的设计进展行 | 保留查看进度、失败原因与重试入口 |
| 孤立要求或报告 | 保留为未归组的设计说明 | 历史数据不会因缺少连线而消失 |
| 拖动、连线、工具参数和完整图导出 | 放在流程画布中 | 切换不重排节点、不修改连线、不触发执行 |

合并的是面向用户的信息结构：已完成的中间处理不再作为工作台对象。分析能力仍参与生成，因为生成工具需要设计约束，删除该能力会改变结果与执行契约。工作台是对现有图的只读分组，不创建新的持久化图，也不删除已有节点。

## 验证

分组单元测试覆盖同次生成、共享来源、分支边界、环与失效连线、孤立记录、部分成功与失败、逐候选评估及空项目。浏览器覆盖 1280px 和 375px 工作台、完整说明、直接引用、失败恢复、详情返回焦点、视图切换和 PNG 导出，并回归既有节点拖动、连线编辑、助手确认与手动执行。

最终通过：6 个分组单元测试、14 个相关浏览器场景、Web TypeScript 检查、修改组件 ESLint 和差异空白检查。工作台切换及导出用例同时检查浏览器运行时错误。已有流程用例显式选择流程画布，并适配当前独立详情工作区；没有改变其保存、失败重试与刷新恢复断言。

截图位于 `output/playwright/design-workbench/`：`designs-1280.png`、`designs-375.png`、`materials-1280.png`、`materials-375.png`。浏览器使用仓库模拟 API，服装图为测试素材；不代表真实模型生成或计费链路验收。
