# Impeccable 全平台重新设计：基线与方案比较

日期：2026-10-25。状态：基线已建立，三个交互候选已实现；等待实际比较后选定方向。本文不表示生产界面已经完成全平台推广。

## 产品依据与范围

产品事实在 `apps/web/PRODUCT.md`。现行浅色系统在 `apps/web/DESIGN.md` 与 `apps/web/.impeccable/design.json`，来源为当前源码；历史深色规范不作为现行依据。候选方向记录在 `apps/web/.impeccable/surfaces/redesign-comparison.md`，尚未取代生产设计契约。

实施前的工作区状态及补丁保存在 `output/impeccable-redesign/initial-status.txt` 和 `initial-worktree.patch`。已有工作台、图片工具、助手、画布和测试修改继续保留。正式 UI 本阶段仅增加开发环境原型路由的免登录判断，其他业务行为不改动。

## 当前体验基线

两名独立审查代理分别进行设计审查和技术检查。设计审查采用当前界面重新采集的 73 张截图，覆盖首页、工作台、助手、画布、11 个工作室模块、面料、趋势、登录、分享及主要浮层。技术检查另外验证焦点、对比度、响应式和控件尺寸。

完整报告与逐张证据索引：

- `output/impeccable-redesign/baseline-a/report.md`
- `output/impeccable-redesign/baseline-a/screenshots.md`
- `output/impeccable-redesign/baseline-b/REPORT.md`

启发式评分 26/40，表示现有基础可用，主要问题在对象连续性和任务效率；不是用户测试分数或合规认证。

| 优先级 | 任务与问题 | 用户影响 | 改造方向 |
|---|---|---|---|
| P2 | 全屏图片工具把作品身份、来源及保存为款式收进“图像”菜单 | 完成修改后需重新查找交付入口 | 常驻对象身份和阶段主操作 |
| P2 | 工作室素材以“图片 1/2/3”或 ID 识别 | 相近方案需要靠记忆匹配 | 缩略图、作品名、来源、修订一致显示 |
| P2 | 比较前的选择图库与比较大图重复 | 采用理由与动作被挤到首屏外 | 收起选择器，保留比较差异和采用动作 |
| P2 | 窄屏长表单和图片工具沿桌面顺序堆叠 | 查看、批注和批准相距较远 | 移动端按查看与关键操作重新排序 |
| P2 | 技术包发布缺少剩余复核事项汇总 | 需逐章查找才能判断是否可交付 | 可定位到章节的缺项与人工复核摘要 |
| P2 | 工作台引用链接、技术包历史 disclosure 的点击区域偏小 | 精细操作和触摸点击更困难 | 扩大交互区域，保留清晰焦点 |
| P3 | 失效分享仅说明失败 | 接收者不知道下一步 | 提示向分享者索取新链接 |

截图文件及源码定位以两份报告为准。扫描器的9条生产提示经检查涉及语义边框、网格和未使用样式等，不等同于9个真实缺陷。

## 三条任务路径的基线

| 任务 | 当前实测步骤 | 上下文或验证限制 |
|---|---|---|
| 继续已有设计 | 首页继续创作 → 作品继续修改 → 输入要求；2次点击+1次输入 | 当前作品与引用保留，是应保持的优点；未发真实模型请求 |
| 引用、生成、比较和修改 | 引用并输入；另进入款式比较、选择两图，打开图片工具与局部重绘 | 素材身份退化、图片工具缺少常驻对象栏；未把一次真实生成连续推进到款式 |
| 款式推进到交付 | 既有款式 → 技术包 → BOM → 复核发布 → 导出此修订；4次点击至模拟排队 | 保留款号和r1，但缺少图与复核摘要；没有真实发布和PDF下载 |

不能将上述不同起点的4次点击与候选中的完整新建交付流程直接作效率百分比比较。全平台推广后应使用同一份真实任务脚本再次测量。

## 可交互候选

启动 Web 开发服务后访问 `http://localhost:3000/prototypes/impeccable`。原型只在开发环境开放，生产构建返回未找到。页面顶部 A/B/C 可以切换，每个方向和项目独立保留本次内存草稿，刷新或“重置全部试用”会清空。偏好按钮只在页面记录，最终方向需在聊天中确认。

| 候选 | 项目入口 | 工作台 | 技术包 | 主要取舍 |
|---|---|---|---|---|
| A 织物档案 | 固定侧栏与项目档案列表 | 并排作品、右侧助手、素材索引 | 作品预览与横向章节 | 资料和导航稳定，但侧栏占用横向空间 |
| B 作品展台 | 顶部导航与作品画廊 | 单幅主作品、缩略切换、按需并排 | 大图与纵向章节 | 作品突出，需关注主操作是否被大图挤出首屏 |
| C 任务接力 | 项目任务列表与阶段队列 | 当前步骤、紧凑并排作品 | 表单为主、右侧对象和章节 | 交付路径清楚，窄屏需压缩任务导航 |

三者使用同一组本地服装样图、项目和材料，明确标注模拟。图片沿用先前本地模型验证素材，来源见 `apps/web/public/prototype-assets/impeccable/SOURCE.md`，已嵌入来源元数据。点击生成只复用已有袖口修改样图，不产生新图像。下载为明确标记非生产用途的 TXT 模拟交付单。

比较任务：

1. 打开秋冬通勤系列，识别当前方案、项目和进展。
2. 引用藏蓝面料，输入袖口修改要求，整理计划，显式确认模拟生成；比较两方案并保存款式。
3. 修改技术包名称和衣长，跨章返回检查草稿，保存，进入复核并下载模拟交付单。
4. 切换项目和方向再返回，检查草稿；试用长文本、缺图、加载、失败重试、空数据和只读状态。

记录完成任务的点击/输入、滚动、返回查找次数、当前对象与修订识别、主操作和作品可见性。页面操作记录辅助观察，但不统计每次键盘输入或滚动，不能当作完整可用性计时器。当前自动化证明功能可达，不代表设计师使用效率结论。

## 验证记录

本阶段已通过 Web lint、typecheck、65个文件/314项单元测试和生产构建。原型浏览器用例14项通过，覆盖三候选桌面/窄屏完整模拟创作与交付，草稿隔离、保存修订绑定、只读限制、校验定位、失败恢复及无API请求。

尺寸检查包括1440×900、1366×768、390×844、375×812和683×384等效可用空间。最后一项模拟200%后剩余布局空间，并非浏览器真实缩放及操作系统辅助技术认证。桌面1440和窄屏390分别采集每候选3页，共18张基线候选截图，存于 `output/impeccable-redesign/prototypes/`。没有更新生产视觉回归金图。

生产全量业务E2E、固定环境视觉回归、真实数据库/队列/模型/存储链路和真实设计师反馈属于选定方向后推广验收；本阶段的隔离原型不能替代这些验证。原型未实现完整业务权限矩阵、全部技术包字段或全部11模块。

## 推广顺序与待办

用户选择后，将所选方案写成新的设计契约，明确共享主题、组件、字体、布局、响应式、对象上下文和状态规则。然后依次实施共享基础与项目入口、创作主链路、款式与交付链路、资料与外围体验。每阶段使用现有唯一主题入口与共享组件，保持旧深链与URL参数。

后续验收应逐项对应基线问题，补业务行为测试、全量业务E2E、固定环境视觉回归与截图复核；真实设计师反馈单独记录。当前不得把未选候选应用到正式业务界面，也不得宣称全平台重新设计已完成。
