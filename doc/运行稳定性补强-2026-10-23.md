# 运行稳定性补强（2026-10-23）

本轮围绕上传、实验提交、取消、异常恢复和导出状态完善业务闭环，沿用现有 API 与工作室界面。

## 行为变化

| 场景 | 原行为 | 完善后的行为 |
| --- | --- | --- |
| 原图确认后进程中断或 Redis 丢失缩略图任务 | 需要用户再次确认上传才能补派发 | API 启动及每 15 秒扫描已确认且超过 30 秒宽限期的 PROCESSING 文件，以原文件 ID 补派发 |
| 缩略图队列不可用 | 请求可能长时间等待，缺少队列错误监听 | 队列命令设置 5 秒超时及有限请求重试，记录连接异常，由后台恢复继续处理 |
| 批量实验某项参考图签名失败 | 提交请求中断，后续项未尝试 | 该项记为未接纳并保留原因，其余项继续提交；重试保持成功项任务身份 |
| 任务已接纳，实验状态尚未更新时执行者被撤权或参考图不可用 | 恢复可能把已接纳项误记为未接纳并清空任务关联 | 先核对持久化生成任务，保留原关联；只有尚未接纳的任务才重新检查权限和准备参考图 |
| 取消发生在任务接纳前，或取消请求暂时失败 | 原进程中断后可能无法继续取消 | 先持久化全部选中项的取消意图，再执行取消；后台等待并处理迟到的同一任务 |
| 待恢复记录超过 100 条 | 持续失败的头部记录可能阻塞后续记录 | 按稳定 ID 游标分批扫描，扫完后回到起点 |
| 历史派发错误与任务真实结果不一致 | 旧错误可能遮盖实际失败原因或出现在成功项中 | 存在生成任务时，以任务状态和错误为准 |
| 导出已过保留期限，但后台清理尚未执行 | 历史列表可能仍显示成功 | 列表按到期时间显示已过期，下载仍沿用服务端权限与期限校验 |

缩略图恢复只主动扫描 PROCESSING 文件，不主动派发 PENDING、READY 或 FAILED 文件。
恢复过程保留队列中的等待和活动任务，不新增文件记录。实验取消沿用现有生成服务协议，
不能保证终止已发送给远程模型的请求；已经完成的任务仍以真实终态为准。

取消意图绑定任务 ID 和尝试编号。若接纳结果仍未知且任务尚未出现，保留该意图，
后台不会为取消操作创建新生成任务。恢复服务关停时等待当前恢复操作结束，停止派发后续项。
