# 统一创作画布

更新：2026-11-14。当前产品约束见 `apps/web/PRODUCT.md`，视觉约束见 `apps/web/DESIGN.md`，实施和验证见 `doc/plans/unified-canvas/IMPLEMENTATION.md`。

## 数据身份与职责

一张 tldraw 画布保存素材摆放、缩放、分组和选择。`CanvasCreation` 保存独立创作目标，即使尚无结果也存在；其 `draft` 保存本次文字、真实参数和有序 `CreationInputBinding`。输入只引用实际节点、资产及版本，不携带旧用途分类或参考权重。

`CanvasCreationRun` 保存执行时的草稿、输入版本和命令快照，以项目内唯一 mutation ID 确认重试。真实工作流执行、生成任务及领域模块记录仍是状态和产物的来源，`CreationRunView` 只负责统一展示，不产生另一套作业队列。

- 创建、连接、改参数、编辑文字只准备目标。生成按钮或明确要求 Agent 执行，才提交真实任务。
- 重跑在同一目标追加执行记录和结果版本，目标身份及位置保持稳定。
- 继续创作建立新目标，并绑定所选结果的准确资产和版本。
- 预览历史不修改当前结果。采用版本是显式更新，记录该次采用并恢复对应执行要求。
- 一轮多张结果归于同一执行；每张结果都能作为下一步的准确输入。

## 命令与恢复

`/projects/:projectId/canvas/creations` 提供列表、创建、读取、修改和执行。修改使用 expectedRevision 和 mutationId，拒绝覆盖更新版本。现有 `run_tool` 入口经 `executeToolCommand` 适配到目标协议，蒙版、旋转和裁剪仍使用已有真实处理器。

前端未知回执以账号、项目隔离存放于 sessionStorage。确认请求复用原 mutationId，不把网络失败解释为重新生成。已离开工作区的响应不能继续更新新工作区；同一目标的在途提交共用 Promise。保存或连线期间的新文字、参数保留为未提交草稿，响应只确认提交版本。

模块表单的本机草稿按账号、项目、目标和来源隔离。布局保存同步目标删除与撤销，资产绑定不误把空目标当作设计资产。生成结果带目标归属，避免在白板重复自动落图。

## 普通生成的输入边界

新普通生成只发送用户原文、明确选择的参考材料及真实功能参数。面料和色卡不产生权重、默认保留条件、人物限制、展示模式或默认负向词。Agent 不能把规划模型扩写后的文字替代用户原文。选中的文字和色值是材料内容，不被转成强制设计用途。

生成编译器不自动运行素材角色识别、用途分类或提示词增强。输入框的提示词增强只有主动点击才调用独立文字服务，回填后由用户核对；普通发送和直接生图不调用它。模型适配按有序引用传图，不以旧 role 重排编号或注入用途说明。明确选择局部重绘、裁剪等功能时，实际蒙版、区域和变换参数仍按该功能契约执行。

旧用途修改和识别的公开接口返回410；旧角色队列由退役处理器消费，不再调用识别模型。新来源记录的用途和权重为 null。原历史快照和已提交任务的冻结执行依据保留，旧标签不迁移成新默认提示词或 Agent 偏好。

## 模块与 Agent

助手的画布操作使用独立的 `AssistantCanvasAction` 契约，与图片生成的 `execution` 互斥。当前浏览器在发送前保存画布和当前创作草稿，提交选择、真实对象ID、页面坐标、父级及几何签名；服务端按已保存文档重新确认对象、素材绑定、锁定和隐藏状态，并读取可见创作目标的真实输入编号与当前账号有权使用的面料。普通选择仍不自动改变助手的显式引用。

模型得到13项独立动作说明及参数schema，一次返回一个动作与当前用户完整原文。讨论、假设、后台观察、未读对象或无法辨认的同名对象不能被当作执行指令。新动作先保存在原消息上下文，随后由发起浏览器领取；排版调用真实编辑器，色卡与面料复用 `CanvasCommandService`，输入连接复用带目标版本的 `CanvasCreationsService.update`。后两者在原事务提交前再次检查当前意图、对象及资料版本；连接只改输入，不运行目标。

`/agent-conversations/:id/canvas-actions/:messageId/{claim,apply,receipt}` 分别负责领取、幂等业务操作和完成核对。素材/连接使用稳定mutation ID；排版按顺序执行并在本机按账号/项目保存已应用证据。服务端核对保存后的对象签名、素材绑定或真实连接，再更新原消息的完成文字。打开面板由浏览器确认可见后回执，手机返回画布露出对应面板。刷新和历史载入不自动重放动作；未知回执的明确继续只补核对，避免重复移动或组合。此协议不新增数据库表或迁移；范围与验证见[助手画布工具](../design/assistant-canvas-actions-validation.md)。

统一目录包含图片工具、色料与改款实验、印花、商品展示、系列和趋势。旧需求分析与独立服装评估退出新创作，需求整理和评价在助手普通对话中回答。带选中素材打开时捕获准确输入；独立打开时保留选择入口，不猜测第一张图片。管理与交付界面、衣橱、实时试穿及服装秀继续使用原工作台。

2026-11-15流程退役：新的设计生成工具清单只暴露文本起草、图片生成、图片修改和图片变换，画布动作使用上述独立契约。`generate_design` 保留为任务／历史的兼容标识，现表示直接图片生成，不再有“需求分析→设计约束→方案生成”的自动链路。`analyze_brief`、`evaluate_design` 仍可解析历史，但新目标、新规划、新参数配置和新执行均停用；已提交的执行记录仍按冻结命令恢复，原图片、版本、关系与报告保留。需求不明确时在聊天澄清，不创建分析节点。

提示词增强：`POST /projects/:projectId/assistant/prompt-enhancements` 只读取当前文字、明确引用及可用图片，返回增强文字与请求编号，不写聊天消息、不创建创作目标、不提交生成。权限、16项引用和4000字符上限继续验证；普通发送保持用户确认的文字。输入框放置星芒图标，完成后可撤销；等待期间文字或引用变更时先保留当前输入，增强结果供明确采用。切换账号／项目／会话或取消时隔离迟到结果。

实验读取实际批次和任务，印花/展示使用文档修订，系列使用真实核心图和候选，趋势保留原资料。领域资源关联到目标后，任务状态、产物和参数投影为统一执行视图；重复关联不会建立第二套任务。

助手读取目标、实际引用和结果版本。准备、执行、重跑和分支共用人工操作的服务命令；保留项目权限、版本校验、幂等和错误恢复。提交、完成、采用和模块记录形成简洁 `creative_activity`；平移、缩放和逐字输入不进入会话。终态事实更新不触发另一轮模型回复，迟到的列表读取不能把已完成记录改回排队。

2026-11-15上下文同步补充：发送聊天时先捕获当前已存在创作目标的草稿，通过原更新接口保存要求、有序引用和参数，成功后携带目标ID及保存后的版本。保存失败、权限不足、版本冲突或切换目标时阻止本次发送，两个输入区的内容继续保留；保存期间的新输入不被迟到回执覆盖，下一次发送再同步。该步骤不创建目标、不发布文本、不运行生成任务。后端核对目标版本，以 `focusedCreation` 提供当前草稿，并优先读取实际输入图片；清空引用后不回退到旧会话焦点。

多色色卡在上下文中保留每项 `{hex, name}` 与顺序，旧字符串色板继续可读。当前节点、补读和冻结历史共用同一内容投影，颜色不再因被当作字符串数组而丢失。

## 图片与连接

`CanvasImageSurface` 统一上传图、生成图和面料图片。旧 appearance、role 和装裱数据仅为快照兼容保留，不影响显示。图片完整等比显示，圆角16个画布单位；无纸张、布边、挂件、滤镜、背景留白或图片阴影。名称和原始像素尺寸在图片上方，字号按视口缩放补偿；缩略图尺寸不会冒充原图尺寸。

图片上下文工具与创作框使用屏幕坐标避让边缘，保持可读大小。短屏使用紧凑输入框。连接开关按账号记住，只隐藏连线和端口，不改变素材、布局或生成输入。旧“资产→工具→资产”展示折叠为资产关系，工具执行记录仍可查看。

## 升级

2026-11-15节点接入：`CanvasCreation.module`增加`text`和`video`，复用现有JSON草稿与运行表，无新增数据库结构迁移。手动文本发布真实`reference_text`节点；视频导入通过`mediaNodeId`关联同项目真实媒体并保留`sourceNodeId`。两者写入`manual`运行记录，统一投影为完成态；不会创建生成任务。AI文本通过`generate_text`及既有模型客户端、工作流尝试与失败记录执行。助手的文本指令使用同一工具，视频仅提供导入上下文。

`CreationInputBinding`允许只有`creationId`的准备态关系，验证自连、环路和项目归属。执行前解析为真实结果及节点版本；固定`nodeId`仍表示明确选中的历史结果。动态文本引用须先保存。前端编号与实际图片输入顺序一致；文字引用不占用图片编号。

`import_reference_video`与`place_canvas_material`复用画布命令幂等、项目权限和布局绑定；`placement=reference`仅准备实际素材，填入目标后不重复自动落图。视频文件经现有签名上传及完成接口验证，READY后通过`/files/:id/content`的受权私有URL读取，支持字节Range；不排队图片缩略图。容器签名不保证每种浏览器都具备相应解码器，播放失败提供重试。

节点内未保存文本位于React编辑器覆盖层及原本机草稿仓库，`stripCanvasTransientDrafts`在布局读取、客户端序列化和服务端保存中去除旧`draftText`，防止未提交内容进入协作快照。模型产物及明确保存正文仍正常共享。具体边界与验证见[添加节点](../design/add-node-interaction.md)。

按顺序部署增量迁移 `20261114140000_canvas_creations` 和 `20261114170000_retire_generation_input_purpose`，生成 Prisma 客户端并构建 shared/ai/db 后更新 API、worker 和 web。两个迁移已应用到本地开发数据库；其他环境按正常发布流程应用。不要改写历史迁移，也不要重放已经提交的旧生成任务。

本次不迁移或删除已有图片文件、位置、分组、资产和历史版本。旧项目由兼容读取继续打开，随后创作遵循新输入规则。
