# 本机工作区草稿

2026-10-27。实现位于 `apps/web/src/components/drafts/`。

## 数据与范围

IndexedDB数据库fashion-workspace-drafts，版本1。主键由账号、项目、编辑器类型、会话或对象ID组成。DraftRecord保存可序列化值、服务端基线、本地revision、更新时间和标签页writer。

首批接入工作流助手、旧助手、工具/素材/决策详情、图片反馈、工作室useStudioForm及独立的印花、色料实验、趋势简报表单。未上传的File、Blob URL、带签名/令牌的URL不落库；保留已上传资源ID。附件尚未上传时刷新需重新选择。草稿不新增后端表、不上传未发送正文，也不自动生成、保存修订或发布。

## 写入与清除

- 300ms合并写入。应用内导航等待flush；进入后台触发flush；不依赖卸载事件完成异步保存。
- 写入在同一个IndexedDB事务内比较revision。多标签通知用BroadcastChannel，通知不替代事务比较。
- 同一基线自动恢复；服务端基线变化不自动覆盖。本机草稿入口显示需要核对，可展开差异、采用服务端、恢复另一份、继续合并。
- 冲突保留额外副本，刷新后仍能读取。显式选择版本后按修订条件清除已处理副本。
- 发送受理/保存成功只清理对应的内容版本；请求期间新增输入保留。
- 明确丢弃会阻止卸载和延迟写入把旧草稿重新写回；不删除另一标签页已写入的新修订。
- 退出/切换账号清理上一账号草稿，并阻止迟到写入。草图沿用既有本机存储清理。
- 存储不可用时保留内存副本，并显示“本机草稿暂未保存”。这不承诺浏览器关闭、清除站点数据或硬件故障后仍能恢复。

## 使用方式

页面由WorkspaceShell提供DraftScope。表单通过usePersistentDraft传入当前value、restore、服务端baseline和稳定objectKey。baseline应来自服务端修订或该修订的可序列化内容，不使用渲染时刻生成的随机值。

同一编辑器内切换对象时，objectKey必须变化；局部编辑器使用useWorkspaceDraftOwner取得原对象ID。保存后的新baseline更新不能清除已经继续输入的新value。需要明确丢弃时使用现有离开保护与条件清除，不直接删除整个数据库。

## 验证

DraftRepository单元测试覆盖CAS、条件删除、账号清理、冲突副本、不可持久化数据过滤；hook测试覆盖刷新恢复、远端基线变化、冲突副本恢复和明确丢弃。浏览器场景覆盖助手刷新、组合输入、工作室表单刷新与分栏偏好。

这是一项本机便利功能。服务端保存状态、人工复核、离开保护和显式交付操作继续独立存在。
## 历史导航保护

支持 Navigation API 的浏览器在可取消的同文档 traverse 事件中先保存，再重放原目标条目；失败留在当前页。保留原popstate恢复和beforeunload路径作为降级。导航注册表按window共享，路由与布局的重载不会分裂保护状态。相关行为按[Navigation API参考](https://developer.mozilla.org/en-US/docs/Web/API/NavigateEvent)实现，实际前进/后退失败与恢复由浏览器回归覆盖。

发送前先刷新本机写入并捕获该会话的修订收据；收到受理事件即按原控制器和修订清理，不等待回复完成。切换会话后的同文草稿、请求期间改写后又恢复为同文的新修订均不会被旧收据删除。请求期间新增正文继续保存；存储清理失败显示本机保存提示，不把已完成请求伪装成未受理。
