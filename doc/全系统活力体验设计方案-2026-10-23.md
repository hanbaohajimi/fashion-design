# 全系统活力体验设计方案

日期：2026-10-23。状态：部分实施，尚未完成全系统方案。已落地范围与验证记录见文末；逐项核对及后续材料视觉方向见《织物视觉语言扩展与实施核对-2026-10-23.md》。

## 1. 总体方向

**让 Atelier 像一间正在创作的服装工作室：作品有存在感，操作有回应，探索有余地，进展看得见。**

用户进入时应感到“这里有我的创作，可以顺手接着做”；操作时感到“我动了它，它准确回应”；等待时知道“事情在推进，我仍可以继续工作”；完成时看见“我的设计又向前一步”。

整体气质延续暖纸、深墨和织物染料色。活力主要来自真实作品、材料差异、动作反馈和创作过程的连续性。技术包、尺寸判断、评审等需要严谨判断的区域保持安静和稳定。

## 3. 四种可感知的活力

### 作品的活力

重要的空间交给真实服装、面料纹理、色样和设计关系。项目首页可以突出一张正在处理的作品；面料以近距离纹理为视觉主体；系列以款式组合展示整体节奏。

同一系统允许不同阅读节奏：首页有一个视觉主角，探索页有适当大小对比，规格编辑页保持规整。用于判断廓形和工艺的图片始终保留完整比例；裁切只用于可进入完整预览的展示封面。项目颜色只影响封面局部、色样及引用标记，服装预览背景保持中性。

### 操作的活力

所有主要动作都具有可解释的反馈：拿起素材时轻微抬起；合法放置位置亮起；落下后安定；建立连线时关系显现；采用候选时选中状态就地变化。

动画跟随事实，保存成功、任务完成等反馈由服务端结果触发。采用候选不会让周围布局突然重新排序；列表筛选保留焦点和滚动位置；鼠标之外，键盘和触屏也能获得同等反馈。

### 进展的活力

让人看见“刚完成什么、哪里等待我、接下来可以做什么”。例如结果产生后提供“比较方案”和“保存为款式”；款式保存后显示与该修订绑定的实验、系列和交付入口；样衣问题复核后显示真实状态变化及下一项待处理问题。

这些信息围绕真实任务和对象组织。设计过程可以反复探索，不做一个强迫所有项目遵守的线性完成百分比。

### 协作的活力

助手围绕当前选中对象表达理解：引用所选参考、说明保留条件、指出一个值得探索的方向，给出少量可选择动作。

例如，在已明确保留廓形且有可用母图时，可建议：“保留这版廓形，分别试试雾蓝与暖灰。”建议先进入可编辑草稿，显示作用对象和变化范围。执行、发布和计费仍由用户明确触发。

团队部分突出真实发生的评论、采用、发布、问题复核。在线状态、未读提示与“上次离开后”摘要都需要明确的数据依据。

以下均为拟议体验。示例名称、数量和文案用于描述设计意图，不代表现有用户数据。

| 区域 | 希望产生的感受 | 拟议变化 |
| --- | --- | --- |
| 登录与首次进入 | 有创作欲，知道从哪里开始 | 一张有来源的服装或材料主题视觉；新用户可从草图、参考图或文字需求开始。示例项目显式标记并由用户选择建立 |
| 项目首页 | 我的工作正在延续 | 首屏突出“继续创作”及当前作品，其他项目维持易检索列表；有真实数据时展示待比较、待评审或可下载的事项 |
| 空项目与空画布 | 空白具有可能性 | 展示“放入一张参考图”“画一张草图”“描述一个设计方向”等短入口；先完成一个动作，再逐步展开复杂选项 |
| 工作流画布 | 素材在手边，关系清楚 | 保留素材、工具、结果的尺寸层次；仅在当前操作附近强化连线和落点；完成后提供新结果定位，不抢走正在编辑的视角 |
| 设计助手 | 有人理解我正在做什么 | 引用对象缩略图、简短理解与建议；建议可忽略、可修正；后台有新消息时轻提示，用户正在读历史时保持位置 |
| 面料库 | 能感到材料差异 | 纹理大图、尺度信息及清晰的成分/克重/来源；选中面料后就地显示加入当前项目的结果，提供返回设计入口 |
| 趋势档案与简报 | 有发现，并能开始尝试 | 有真实内容时采用一条主线与次级资料的编辑式层次；将色样、廓形和原文来源放在一起，连接到“据此建立设计简报” |
| 款式与版本 | 看得见自己的选择和成长 | 当前采用方案居于主位，版本按实际修订对照；采用、否决和保留比较的理由可以回看，方便继续分支设计 |
| 色料实验与印花 | 愿意低成本尝试 | 保持矩阵位置稳定；参数变化直接反馈预览；已完成单元格就地显现，失败单元格保留重试入口；预览和真实生成明确区分 |
| 品牌与系列规划 | 多件作品正在成为一个整体 | 品牌规则与引用案例并置；系列用真实已选款式、色组和待补位置表达结构；空位允许有意保留 |
| 技术包、样衣与团队评审 | 每个问题都能向前推进 | 重点展示当前修订、未复核项和照片锚点；动作成功后就地更新；用真实审阅记录表现协作，不增加持续装饰动画 |
| 商品展示与导出 | 作品完成了一次交付 | 预览所选修订的成套效果；后台导出完成后给出清楚的下载与返回入口；到期、失败和撤权都有准确状态 |

## 5. 一段完整的体验编排

以“继续一件外套设计”为例：

1. 进入首页，看见该项目真实封面和“继续创作”。若没有浏览历史，仅表达“最近更新”，不声称这是上次停留的位置。
2. 返回工作台，保留可恢复的视图和对象。缺少有效状态时使用稳定的默认视图，不让用户先经历一段开场动画。
3. 将面料放入画布：拖拽过程有明确合法落点，放下后轻微安定，素材的身份、缩略图和用途立即可见。
4. 选择母图和面料，助手先展示引用及保留条件，用户确认草稿后执行。
5. 任务等待期间显示已知阶段；已有绘画动画作为可暂停的陪伴。用户仍可操作其他分支，进度未知时使用诚实状态文字。
6. 结果真正到达后，在结果位置进行一次短显现。若结果位于屏幕外，提示“有新结果”，由用户决定定位。
7. 用户选择方案后，选中状态原地落定，出现“比较方案”“保存为款式”等与当前对象有关的后续动作。
8. 保存修订后，可沿该修订进入实验、系列或交付；离开后再回来仍能找到真实结果。

这段体验把画布、助手、任务、款式和交付连接成连续创作，而每个模块仍可独立使用。

## 6. 视觉与动效规则

### 色彩与材质

- 延续现有暖纸、深墨、茜草色主操作及语义状态色。增加视觉活力时，优先调整作品比例、内容密度和色样使用，而非同时更换全站色板。
- 面料、色样、草图和作品保留不同的内容表现；表面纹理只出现在外围空白与材料容器，文字、规格表及色彩判断区域保持干净。
- 展示标题可以使用现有衬线字体，编辑和说明保持清晰的中文无衬线字体。关键提示不缩成难读的装饰小字。

### 动效强度

| 动作 | 建议时长 | 表达与边界 |
| --- | --- | --- |
| 按压、切换、选中 | 90–140 ms | 快速确认操作，提交不可被动画阻塞 |
| 悬停、聚焦、拖拽抬起 | 140–180 ms | 用轻微位移或层级变化表达可操作性，焦点轮廓独立保留 |
| 面板、素材落定 | 180–240 ms | 与原位置有连续关系，避免挤动其他控件 |
| 用户触发的新结果显现 | 240–320 ms | 一次性，等图片解码后出现；刷新或重新挂载不重复庆祝 |
| 活跃任务 | 随真实任务存续 | 前景可见区域保留有限运动，任务完成即停；历史任务静止 |

建议值为设计目标，实施时与现有 `--duration-*` 及别名统一管理。当前多数进入/布局时长共用 180 ms，需要更慢的结果显现时新增语义明确的 token，不全局拖慢交互。

低频结果显现可用短暂明暗和位移变化；编辑控件不做跟随鼠标的磁吸；无限画布不额外施加页面滚动惯性。避免新增持续粒子、自动轮播和全屏完成动效。

减弱动态模式取消位移、缩放与循环运动，仍保留静态选中、状态文字和结果提示。隐藏页签和不可见区域不继续播放装饰内容。绘画媒体目前已有生产开关及来源说明，后续视觉素材优先使用明确可复用的自有内容。

## 7. 数据与实现边界

| 体验能力 | 可复用基础 | 需要补充或确认 |
| --- | --- | --- |
| 最近项目主视觉 | `Project` 中的封面、名称、更新时间、资产数量 | 自动挑选新封面的规则；用户手选封面的优先级 |
| 继续上次创作 | 已有 active-board 记录与项目路由 | 用户级浏览记录、有效对象和视图状态；跨设备恢复需持久化契约，不能用 `updatedAt` 冒充访问时间 |
| 结果出现与下一步 | 工作流任务状态、候选资产与现有保存/比较入口 | 首次呈现与重放的去重键；移动端定位；动画期间的输入优先级 |
| 项目进展摘要 | 已有款式、修订、样衣问题、评审和导出事实 | 统一摘要读取接口及权限过滤；首页避免逐项目加载完整工作室数据 |
| “上次离开后”的新进展 | 现有任务和审阅记录 | 稳定事件 ID、用户已读水位和去重；没有这些数据时只显示带时间的最近记录 |
| 助手下一步建议 | 引用、上下文、提案与已有能力目录 | 适用条件、对象版本与权限；服务端验证过期建议，避免依靠 UI 发起越权或重复任务 |
| 团队在场感 | 已有成员与评审记录 | 真正的在线状态需要独立 presence 机制；优先呈现可核实的评论和修订活动 |

新摘要只读取已有事实，不以刷新页面为理由调用图片模型或视觉分析。所需契约优先放入 `packages/shared`，沿用现有权限和不可变修订机制。

## 8. 建议实施顺序

### 第一阶段：让日常操作有回应

范围：共享按钮、选中状态、拖放、节点结果显现、局部成功/失败反馈、空项目入口。重点建立完整的“操作—反馈—下一步”节奏。

优先文件：`components/ui.module.css`、`components/TaskFeedback.tsx`、`styles/design-system.css`、`modules/board/workflow/WorkflowNodeShape.tsx`、`WorkflowAssetWorkspace.tsx` 及对应样式。

完成条件：上传、连线、执行、结果到达、采用五个关键时刻反馈统一；重载不重复播放结果动画；错误状态仍可重试；视图与键盘焦点不被抢走。

### 第二阶段：让首页和探索空间有创作气息

范围：继续创作区域、项目卡片的内容层次、面料纹理展示、趋势主线与空态。保持项目搜索、列表密度选项及移动端可用性。

优先文件：`modules/projects/ProjectLibrary.tsx`、`ProjectCard.tsx`、`EmptyState.tsx`，`modules/fabrics/FabricCard.tsx`，`modules/trends/TrendArchive.tsx`、`TrendCard.tsx`。

完成条件：有内容时一眼找到作品与继续入口；没有内容时一步开始；页面的大图使用真实授权素材，保留加载、缺图和无数据状态。

### 第三阶段：让整个创作流程持续向前

范围：可追溯进展摘要、助手上下文建议、款式到实验/系列/交付的接续、评审活动及离开后返回。

优先文件：`WorkflowAssistantPanel.tsx`、`modules/studio/StudioWorkspace.tsx`、`StyleLibrary.tsx`、`ExperimentPanel.tsx`、`PlanningBoard.tsx`、`TechPackEditor.tsx`、`SampleRounds.tsx`、`PresentationSets.tsx`；摘要与已读水位按实际需要扩展 API 和共享类型。

完成条件：从参考图到可交付修订的完整路径无需重新寻找同一资产；下一步建议有适用条件、可忽略且不自动执行；进展显示与实际任务、权限和修订一致。

三个阶段构成全系统方案。第一阶段是建议起点，不代表整个目标已完成。

## 9. 后续实现的验收标准

1. 让设计师分别体验首次进入、继续旧项目、长等待后出现结果、失败后恢复、评审完成五个场景，确认是否感到有回应、容易继续和可掌控。用户感受需实际验证，不能只由截图或测试通过推断。
2. 检查 390px、常见笔记本宽度和大屏；缩放、触屏与键盘操作都保留关键动作，不让装饰侵占工作区。
3. 同一项任务从新建、等待、完成到刷新重进，状态与结果保持一致；多任务并发时限定运动范围；失败、取消与未知进度表达准确。
4. 使用减弱动态模式；保留可见焦点、屏幕阅读器状态提示、文本标签和对比度。固定截图与真实动效分别验收。
5. 改动后运行 Web 类型、lint、组件/交互测试及相关浏览器流程；更新视觉基线前人工审查。涉及全站 token 的阶段应检查所有受影响页面，不能沿用旧“仅画布可变”的范围。
6. 动效优先使用 transform/opacity；通过浏览器性能记录检查典型与密集画布，不把“使用 CSS 动画”当作流畅性的证据。记录返回继续设计所需操作数、结果出现到查看的路径和中断次数，以实施前后对比评估改善，不提前虚构收益。

本提案的优先取舍：先完成真实、连续的创作反馈，再扩展首页表现和项目记忆。每个新增视觉与建议都应帮助用户更容易开始、更清楚地判断、更顺手地继续。

## 10. 实施记录

- 登录页新增自有 CSS 织物习作，桌面双栏、手机纵向排列，登录表单保持完整可用。
- 首页新增真实项目作品展示和继续入口；记住当前账号在本机访问的项目及工作室功能。无有效记录时使用项目列表的最近更新项，搜索及归档视图不展示此区域。
- 新增只读 `GET /projects/:projectId/studio/creative-summary`，复用项目访问检查，仅返回款式、未归档候选和技术包计数。首页只请求当前展示项目的摘要，读取失败回退到项目元数据。
- 画布按账号与项目保存本机视角和选择；无效或过期对象回退。新增方案由真实同步结果触发提醒，不自动定位；图片加载后进行一次短显现，刷新和重复同步不重复提醒。减弱动态模式保留状态文字。
- 助手依据当前选择提供素材梳理和设计讨论入口，带入引用并填写可编辑草稿，不自动发送或执行。
