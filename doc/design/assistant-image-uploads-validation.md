# 聊天参考图片上传与恢复验证

日期：2026-11-10。本阶段补齐从现有设计聊天选择、粘贴或拖入参考图片，到私有文件、项目素材和当前消息引用的连续路径。继续使用无限白板内同一份聊天和毛绒织芽，不新增另一套助手。

同日后续已将新聊天上传与白板摆放分开，当前行为以[聊天参考预览与明确放置](assistant-reference-placement-validation.md)为准。下文保留本阶段当时直接接入白板的实现和测量事实，不将其历史数据当作后续版本已重新验收。

## 实际行为

- 输入区提供“上传图片”，支持多选 JPG、PNG、WebP、HEIC/HEIF，单张上限 50 MB。粘贴图片时保留原正文；混合文字插入当前光标位置。拖入输入区只由聊天接收，避免画布重复接收同一文件。普通文本粘贴继续交给输入框。
- 图片按选择顺序经过签名、原文件直传、完成确认、缩略图和项目接入，再追加到当前草稿引用。只在用户明确发送后发送聊天消息；上传入口本身不创建对话、提交生成任务或运行角色识别。
- 复用项目中的同一参考文件，重复操作回执不新增第二份素材和摆放。接入前保存白板；失败保留正文和原操作，成功不移动画布视野、不重建聊天。已有节点的历史删除摆放保持删除，不因再次引用强制复活。
- 附件列表显示准备、上传、处理和接入状态。可暂停未提交的上传，再继续或移除；已经接入中的操作不伪装成可撤销的上传。准备中、失败或待续办的图片会阻止发送，避免漏图。待上传图片与正文提及、显式引用合并计算 16 项上限，整批拒绝超量，不静默截取。
- 完整接入编号和放置位置在发命令前写入本机记录。响应丢失时继续使用原编号和位置，不重复上传；引用完成并确认草稿已落盘后才清除恢复记录。
- 刷新只恢复待办提示，不自动重发。文件尚未直传完成时需选择原文件；已算出摘要则核对 SHA256，未算完时核对名称、大小和格式。只保存元数据和回执，不保存 File、Blob 地址或签名地址。
- 上传完成但处理尚未就绪时只继续检查处理状态；明确缩略图失败后，重新准备原文件。刷新后没有原文件会要求重新选择。重选读取失败有明确提示，重载后迟到的文件读取不启动旧操作。
- 账号、项目、编辑器和对话隔离恢复记录。切换会话、账号或卸载时停止请求和迟到结果的界面应用；这不等于取消已经到达服务端的事务。原会话可使用同一回执续办。退出后的草稿清理沿用现有账号规则。

## 服务端与发布边界

共享画布命令新增 `import_reference_image`，只接收文件 ID、操作编号和可选位置，不接收客户端伪造的名称、尺寸或图片地址。服务端核验项目编辑权限、真实操作者的文件访问权、文件就绪与图片元数据、私有原文件可用性，再复用原有画布事务和幂等回执。

`WorkflowsService.applySystemMutation` 可显式指定真实操作者；新导入命令用该身份检查文件并记录 actor，其他既有调用保持默认行为。解决项目编辑成员上传的私有文件被错误地用项目所有者身份核验的问题。事务再次验证项目与成员权限，不新建数据库状态副本或迁移。

必须区分入口与现有后台：新入口不自动发送消息或生图；正式缩略图后台已有可选视觉摘要安排，因此不能声称上传绝不触发识别或模型调用。本阶段实际集成直接调用缩略图处理器，不传视觉摘要适配器，未调用付费模型、未启动正式 Worker。

前端、API 和 shared 契约应一同发布。旧 API 会明确拒绝新命令，前端保留可继续的附件，不以未知结果冒充成功。

## 输入区与窄屏

引用、附件和待办提示放在同一独立滚动区，正文及发送操作位于滚动区外。取消此前覆盖正文的 sticky 操作行，内部引用及附件列表不再各自嵌套滚动。普通手机高度为引用保留更多空间；320×400 时压缩顶部低频操作、隐藏视觉上的重复输入标签，同时保留可访问名称、至少 64 px 正文和 44 px 触控按钮。

实际检查先后发现引用区缩到 4 px、短屏末项移除按钮裁切，以及普通手机高度两张引用的第二项部分裁切，修复后定向复测。失败截图与 trace 保存在 `output/playwright/assistant-image-uploads/initial-failures/`，不把首次通过用例扩大为所有屏幕均通过。

API 第 5 项实际经过 Nest HTTP 签名、MinIO PUT、完成确认、真实缩略图处理器、参考导入和成员缩略图读取。使用有效 37×55 PNG，核对原始字节、WebP 尺寸、重复导入和来源。其余用例覆盖编辑成员文件归属、回执去重、未共享或撤销成员拒绝、只读、未就绪、文件丢失和归档项目。使用隔离账号与项目，结束清理；认证身份、限流和入队适配器受控，不能称为实际登录、正式队列或真实模型验收。

浏览器覆盖桌面/手机多图、光标和正文、混合粘贴、拖入、直传失败、处理失败、未知回执、刷新重选、暂停移除、账号/会话切换、只读、格式、数量上限和短屏。补充实测首次尚无会话时上传及刷新都不建会话，明确发送只创建一次，发送后刷新不会复活旧草稿；多图处理中继续输入采用最新正文并保留光标，刷新恢复完整引用。API与文件响应用测试夹具控制，第二图的额外字节只用于区分行为，不构成图片有效性或质量证据。

## 画面与性能证据

目录：`output/playwright/assistant-image-uploads/`。

- `preparing-*`、`ready-*`、`retry-*`、`two-references-*`：真实浏览器截图；`short-320-400.png`：最小短屏下正文、发送与末项引用。
- `tour-1440.webm`、`tour-320.webm`：上传、续办、完成引用的浏览器短录屏。展示图片使用仓库已有原型素材，未新调用生图。
- `clip-1440.json`、`clip-320.json`：四态裁切结果。320 px 启用触控模拟、暗色系统偏好和减弱动态，实际仍使用平台现行暖白主题，不代表完整深色皮肤或实体手机验证。
- `performance-before-input-fix.json`：100 对象首次独立测量。准备前/完成后平移分别 59.84/59.87 fps，等待图片期间连续输入只有 50.68 fps、长帧 10.506%，未达到目标。
- `input-profile.json`：输入 CPU 诊断；发现关闭的素材选择窗口仍随每个字重新构造整套素材行，已缓存匹配、选择与缩略图行，数据、搜索或选择变化时才更新。
- `performance.json`：修复后独立三段测量原始数据，结果见下表。

2026-11-10北京时间16:40，Windows、Chromium145.0.7632.6、无头、DPR=1、16逻辑线程；单worker、原生时钟/rAF、无trace/录屏/并行检查，本地受控API，初始100对象。同样输入强度下结果为：

| 场景 | 平均fps | >33.3ms帧 | 事件至下一帧P95 |
| --- | ---: | ---: | ---: |
| 准备前平移白板 | 59.87 | 0.111% | 8.0ms |
| 图片等待签名期间持续输入 | 59.17 | 0.901% | 15.9ms |
| 完成引用后继续平移 | 59.97 | 0.056% | 6.9ms |

三项均达到≥58fps、长帧<1%的目标。持续输入最接近门槛，后续更大项目和实体设备仍需单独检查；不把这组三段数据推广为所有上传阶段或生产环境结论。
