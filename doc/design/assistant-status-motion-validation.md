# 设计助手轻量状态动效

更新：2026-11-15。用户在消息结果展示完成后明确选择“图标变化为主，文字和结果块保持稳定”，并提供StatusMark与ThoughtLine源码作为参考。

## 接入与呈现

`StatusMark.tsx` 根据提供的StatusMark适配为纯图标组件。保留虚线环、运行圆弧、完成圆环与勾号、失败叉号；补齐部分完成、结果待确认和取消状态。尺寸16px、描边1.5，颜色使用当前品牌和错误语义token。步骤中的图标为12px，不改变正文标题、文字颜色或结果块排版。

CSS按SVG归一化路径长度插值圆环和勾号；运行圆弧1100ms匀速旋转，成功描边220ms，颜色过渡160ms，沿用现有 `--ease-enter`。没有引入新的依赖，也没有为了这段局部动效加载另一套图标。对提供源码中的删除线、完成后文字变淡和默认亮绿色做了适配：图标组件完全不接管旁边的文字，现有结果标题继续保持14px／600字重及全透明度。

状态只由实际回执和已有创作状态驱动。排队／已提交是静态虚线环，执行中是圆弧；成功、失败、部分完成、取消与待确认均有不同图形和文字。没有自动结束定时器、模拟百分比、庆祝弹跳或为了展示动画而等待。快速动作可以直接显示最终状态；初载历史直接画出终态，不重播描边。

## ThoughtLine接续

现有ThoughtLine继续默认只显示一行星芒、真实阶段和计时，点击后才展开实际观察到的步骤。文字扫光、模糊过渡、完成后的文字透明度变化已移除，只保留星芒1600ms轻呼吸。计时使用等宽数字及固定宽度槽位，标签截断与完整可访问名称配合，避免窄面板中挤动其他内容。

阶段更新保留用户的展开选择；重复阶段不重复记录。真实结束时折叠，指针折叠200ms、键盘直接到位，手机触区44px。首次终态冻结计时，后续轮询不会继续增加耗时；再次请求或重试根据新的attempt与实际开始时间重置。失败或停止不把最后阶段标成完成。历史完成消息不补造阶段和计时。

服务端“正在理解画布与设计过程…”占位不再与ThoughtLine上下重复展示。执行反馈到达时，在原消息中由StatusMark接替ThoughtLine；结果标题、对象范围和回执状态继续使用前一阶段已核实的数据。助手消息本身不因状态变化重新做整块入场，结果区域无移动、淡入或缩放动画。

## 生命周期与无障碍

复用 `useMotionActivity`：收起、滚出视野和页面后台均暂停图标循环，运行状态仍保持原值；后台确认完成后恢复直接显示静态完成状态。减弱动态关闭旋转和描边过渡，保留状态图形及真实文字，思考计时每秒更新。

Standalone StatusMark有中文可访问名称；与结果标题同时使用时图标为装饰，状态由现有消息区域播报，避免重复朗读。计时不每0.1秒触发React渲染或辅助技术播报。

## 验证

证据统一位于忽略的 `output/assistant-status-motion/`。动画逐帧采样使用真实CSS、真实组件和tldraw执行，网络回执由隔离夹具控制；不调用真实模型或图片生成。

- Web定向Vitest三个文件31项通过：所有图标状态、无自动完成、默认折叠、阶段去重、重试时间、首次终态冻结、失败／取消，以及既有反馈事实规则。
- 新增8项单worker Chromium用例：1440px桌面与320px手机的思考→执行→成功交接，键盘展开，刷新静态终态，收起／离屏／后台暂停，减弱动态，以及失败、部分完成、取消和排队标记。逐帧数据记录在 `transition-1440.json`、`transition-320.json`。
- 结果转换期间核对标题颜色、透明度1、字重600、无删除线；结果块与标题坐标不漂移，块宽高保持不变；勾号描边确有中间值并在终态为0，完成后没有运行中的图标动画。
- 继续回归17项消息展示用例与1项既有ThoughtLine用例，覆盖320／360／400／420px、实际浮窗、长名称、失败、部分完成、原位更新和过程展开。裁切审计使用消息父容器以及Tooltip所在浮窗／页面，不忽略组件自身。
- Web类型检查与目标ESLint通过。没有新增业务接口、数据库迁移或后台执行路径。

`status-transition.mp4` 从真实浏览器录屏裁取实际400×640助手区域，未改变速度；`thinking-1440.png`、`done-1440.png`、`thinking-320.png`、`done-320.png`为对应真实状态截图。初次测量时修正了测试观察器注册顺序及隐藏元素的查询方式，最终断言检查实际状态更新，不靠等待固定时间推断完成。
