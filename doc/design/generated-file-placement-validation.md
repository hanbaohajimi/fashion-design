# 从生成文件返回画布继续创作

日期：2026-11-10。本阶段承接[生成文件浏览](generated-files-validation.md)和[图片历史](canvas-object-history-validation.md)，补齐“历史结果已移出画布，但仍想继续编辑”的断点。

## 行为

- 白板项目菜单“生成文件”中，尚未摆放的生成图片显示“放入画布”；归档图片显示“以新版本放入画布”。只读、流程视图和白板未就绪时不提供写入操作。
- 普通图片沿用原资产和已有候选节点，只增加新摆放；归档图片创建活动的恢复版本并保留来源和原归档记录。新位置以点击时的画布中心为参照，不移动其他对象或白板视野。
- 放置成功后保留列表及其阅读位置，提供“查看已放入的图片”；相应条目的操作切为“查看已放入的版本”，避免同次浏览连续创建副本。定位后通过既有图片工作区继续编辑。
- 放回旧图只显示放置反馈，不再误报“新的设计方案已到达”。普通生成任务的到达反馈不受影响。
- 未保存的白板先保存，失败时不发放置请求；聊天实例、草稿、光标及原摆放保持。成功结果直接应用到现有白板，不重建编辑器。
- 发送前持久化完整操作编号、资产、归档选择及位置；未知结果保留“继续确认放置”。刷新不自动重发，确认时沿用原编号和位置。关闭、账号或项目切换停止请求及迟到结果的界面应用；服务端可能已经完成，仍以原编号查询。
- 同一浏览器窗口连续点击共用在途请求；两个窗口同时提交由本机草稿事务保留先到的请求，另一个窗口显示原待办；不留下不可执行的冲突命令副本。明确权限/参数拒绝可更正重试，未知网络或服务端结果继续使用原编号。

## 服务与边界

`CanvasCommand`新增 `place_generated_asset`，复用 `POST /projects/:id/canvas/commands`。请求只包含资产ID、明确的归档选择和可选位置，不接收客户端文件地址。使用项目编辑权限、现有画布事务锁和命令回执。无需数据库迁移，不增加轮询、模型请求或任务调度。

服务端复核：资产属于当前项目、不是普通上传或内部蒙版/探针、归档状态与用户看到的状态一致、私有原图为非空图片；存储检查后再次核对项目是否仍可编辑。新版本、设计来源、候选节点、摆放和回执在同一事务中完成，失败不留下半份恢复。既有删除摆放保持删除，其他副本的坐标和绑定不变。

前端新增 `use-generated-file-placement.ts`，按账号/项目/编辑器保存待办，直到返回结果在白板中应用并完成保存检查后才清除。记录删除同时比对修订和完整内容，防止迟到操作删除另一份待办。关闭并不声称取消了服务端事务。账号退出沿用已有私有草稿清理规则，不承诺退出后仍保留原待办；同账号刷新/重新打开已验证可续办。

本次放置范围是 DesignAsset 生成图片。视频、音频与导出文档仍从各自来源继续，不提供错误的图片编辑入口。外部历史URL沿用原行为，未在新命令中任意抓取；head检查不能保证检查后文件永远不变化。

证据目录 `output/playwright/generated-file-placement/`：
