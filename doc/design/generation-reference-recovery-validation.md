# 生成参考图的排队与重试恢复

日期：2026-11-09。承接[生成参考图完整性验证](generation-reference-integrity-validation.md)，本轮只处理任务等待期间地址过期及同一任务重试时的输入一致性。没有界面调整、付费模型调用、生产 Worker、提交推送、全仓检查或 CI。

## 已复现的问题

新设计、普通改图和编号意见修改均把临时下载地址留在任务里。构造失效签名并确认私有存储实际返回 HTTP 403 后，三个真实队列场景全部因参考下载失败而中断。

## 实现

生成接纳时把经过权限核验的私有对象键保存到任务 `compiledPrompt.imageSources`，与当时的输入URL逐项对应。没有新增数据库表或迁移；该记录是内部生成数据，外部生成请求不能注入。

核验允许当前项目的有效设计资产、本人文件、明确共享到可访问项目的文件，以及仍公开的预设面料或趋势素材。文件原图和已登记的缩略图都能识别；不能因为知道另一个账号的地址就获得签名权限。外部网站地址继续经过原有加载限制，不被推断为私有文件。

Worker每次尝试用内部对象键生成新的下载地址，同时更新原图、旧数组及带用途的数组，保留顺序、用途和强度。同一文件的多个地址别名使用一致的新签名，原始任务记录不被修改。记录损坏、重复映射或与当前任务不符时，在签名前明确拒绝；存储签名能力不可用时给出可重试的错误。

编号意见和扩图准备原图时，优先使用接纳时核验的对象键。同一任务重试期间，即使母图记录的URL已经被换掉，也不拿另一张图制作编号参考。局部重绘的母图和蒙版继续使用既有冻结副本机制，额外细节参考才进入本次地址更新。

- 新设计、普通修改、编号意见、参考文件缺失四条已有场景继续通过。
- 三条失效签名场景先确认旧地址无法下载，再验证实际提交的全部图片字节仍正确。
- 编号意见的第一轮供应商传输受控失败，同时把母图记录替换成另一个URL。第二轮仍上传相同原图、编号图、面料和细节；只生成一份结果、计次一次。两次请求均为本地受控传输。

## 边界与后续

- 本次保证已核验的文件身份和同一队列任务的输入一致性；没有对每张普通参考另存永久字节副本。若底层同一对象键被外部覆盖，不能依靠此记录恢复旧字节。
- 缺少内部文件记录的旧任务保留原行为，不自动从任意旧地址取得签名权限。文件确实丢失仍会明确失败；外部网站图片没有新增长期保存承诺。
- 用户发起新任务的重新接纳仍按现有项目访问与素材规则校验。供应商真正理解参考用途、参考强度和最终作品质量，需要另外验证。
- 本轮Lovart远程访问没有返回可核验正文；没有使用本机访问该站，也没有增加官方能力对照结论。后续继续核对扩图等衍生入口的实际参考处理、结果连续编辑和交付路径。
