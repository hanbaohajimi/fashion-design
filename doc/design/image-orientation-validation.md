# 图片旋转、镜像与新版本验收

日期：2026-11-09。此轮沿用森织暖白、深绿与已认可的织芽形象，扩展图片工作区；不代表平台已与 Lovart 全面等同。

## 本轮行为

- 从无限白板中的作品进入原有图片工作区，使用“旋转与翻转”。支持左右 90°、−180° 至 180° 自定义角度、水平/垂直镜像。
- 修改立即预览，可查看原图、返回预览和复位。比较原图不清空参数；旋转按钮按当前可见画面的方向操作，包括已镜像的情况。负数和小数可以连续键入。
- 显示最终输出尺寸；90° 自动交换宽高，自定义角度显示完整边界，空白区域为透明像素。原图的标注与评论不混入新的图片像素。
- 只有显式点击“保存为新版本”才调用现有 `transform_image` 命令。使用现有任务、幂等键、父图/根图、设计步骤和新结果回看机制，不调用模型、不消耗生图额度。
- 方向草稿使用既有账号、项目和图片隔离的本机草稿机制；关闭、重新进入可恢复。复位或已确认提交后清除该方向草稿。提交结果未确认时保留原操作并禁止发起第二份变换，允许原操作重试。
- 手机顶部压缩为对象信息、图像菜单和关闭。下载、分享、保存款式在图像菜单中；图片继续支持触控缩放与适合窗口。方向参数独立滚动，保存按钮不覆盖控件。菜单支持 Escape 关闭并恢复触发器焦点，点击外部收起。

## 输出契约与兼容

共享 `imageTransformSchema` 新增可选 `rotate`、`flipHorizontal`、`flipVertical`，旧裁剪/缩放请求和历史任务无须迁移。`width`、`height` 始终指最终输出，每边 16–8192 px，总输出最多 3200 万像素。

处理顺序固定为：EXIF 正向化 → 按正向原图坐标裁剪 → 顺时针旋转（负值逆时针）→ 按旋转结果的水平/垂直轴镜像 → 最终缩放 → PNG。Sharp 的镜像操作在同一处理管线中先于旋转，因此实际处理先取得旋转后的原始像素，再镜像与缩放，避免视觉预览和保存方向不一致。中间不使用有损编码。缩略图、来源关系与任务结果沿用原处理器。

`rotatedImageSize` 使用与当前 Sharp/libvips 一致的最接近像素取整；浏览器预览与任务参数复用。预览变换局限于图片工作区，不逐帧重绘整个白板。

本轮无数据库迁移和新轮询。上线时需一并发布 Web、共享包、API 与 Worker；旧 Worker 的严格参数校验不能处理新增字段。基础图片变换继续受现有项目编辑权限与来源权限校验约束。

## 性能测量与修复

初次测量暴露出拖动滑块时的实际卡顿：每次角度变化都令 `WorkspaceDraftStore` 发出通知，`WorkflowCanvas` 的订阅因此反复重绘白板。注册表现在持续保存最新草稿值，仅在所属对象、未保存/冲突/锁定状态或基线/纪元改变时通知工作区；未降低预览更新频率，也未删去草稿保护。

2026-11-09 12:21:29（北京时间）完成同场景复测。Windows、Chromium 145.0.7632.6、headless、DPR 1、16逻辑线程；后台白板有100对象（30图片、60便签、10色卡）。编辑600×800图片，每组30秒，使用原生时钟/rAF和真实鼠标拖动滑块；拖动组记录340次输入。测量期间没有并行测试、编译或视频编码。

| 场景 | 平均 FPS | 帧间隔 p95 | >33.3 ms 帧 | 输入至下一帧 p95 |
| --- | ---: | ---: | ---: | ---: |
| 修复前连续旋转 | 42.05 | 33.4 ms | 12.02% | 146.8 ms |
| 修复后静止预览 | 60.00 | 16.8 ms | 0% | 无输入 |
| 修复后连续旋转 | 59.60 | 16.7 ms | 0.17% | 11.7 ms |

本机测量满足平均至少58 FPS、>33.3 ms帧少于1%的目标。这里测量的是覆盖在白板上的图片编辑工作区，不代表实体手机或超大图片性能，也不是上一轮白板平移测试的替代。原始数据为 `performance-before.json`、`performance.json`；用例为 `tests/e2e/image-orientation-performance.spec.ts`，通过 `IMAGE_ORIENTATION_PERF=1` 单独运行。
