# 图片编号意见与参考图验证

日期：2026-11-09（北京时间）。本轮把图片上的位置、编号和修改说明接入现有图片编辑执行链路，继续沿用森织暖白、深绿和织芽形象。没有增加第二个助手，也没有调用真实生成供应商。

## 已实现的行为

- 在图片工作区选择“添加评论”，可以点击图片放置编号，或保留整图意见。点击现有编号或列表“编辑”修改同一条意见，不创建重复意见。未处理的草稿不会被其他标记覆盖；需要先添加、更新或取消。
- 图片编号与意见列表共用原始序号，包含整图意见。只选中第 2 条时，任务仍使用编号 2，不重新编号成 1。已有的 100 条意见上限不变；达到上限仍可编辑和删除。
- 每条意见可以明确勾选相关画笔、矩形、箭头或文字标注。不再在未关联标注时自动把整张图的所有标注发给任务。
- 新建/编辑状态、文字、位置、当前勾选和标注关联按现有账号、项目、图片草稿范围保存。关闭前完成本机草稿写入；保存到项目后先更新本机基线，再继续提交。空选择刷新后仍为空，不自动执行。
- 保存、提交及等待确认期间锁定相关控件。丢失回执后保留原指令和操作编号，刷新只提供原操作重试。服务端拒绝过期意见修订、未知意见和无项目权限的执行。
- 标记点击区域保持 44×44 屏幕像素，不随图片放大而扩大。草稿标记支持方向键微调、Shift 加快。图片外点击、右键、移动超过 6 px、取消手势和多触点均不会误放置标记。
- 任务使用未标记原图、编号参考图、额外参考图的顺序。额外图片的用途、权重和顺序保留；超过输入上限时明确拒绝，不静默丢掉参考。
- 标记只绘制在独立参考图与用户主动导出的标注图片上。原资产不被覆盖。提示词明确要求生成结果不要包含编号和标注，但模型是否遵循这一要求仍需真实供应商质量验收。

## 本轮实际发现并修复的问题

1. **服务器保存后立即刷新出现基线不一致。** 增加持久草稿 checkpoint，将新的服务端基线与保留的编辑状态一起写入，再继续执行后续请求。
2. **320 px 下快速关闭、重开、刷新偶尔丢失编辑状态。** 原关闭操作先卸载，草稿仍在异步写入；现在等待明确的草稿快照持久化再关闭。修复前重复三次有两次失败，修复后三次全部通过，后续回归也通过。没有靠增加等待时间掩盖问题。
3. **图片显示 200%，左下角比例文字仍为旧值。** 手势预览直接更新比例节点，原 JSX 的多个文字节点与后续更新不同步；改为单个文字内容。新增浏览器断言在修复前失败、修复后通过。
4. **从滚动后的意见列表进入编辑，输入框只露出一部分。** 保留浏览器正常的焦点滚动，使正在修改的文字进入可见范围。完整可见性断言在修复前失败、修复后通过。

- 1440 px 与 320 px 的编辑位置、勾选和草稿恢复。
- 误触、取消、多指、右键、200% 下的标记点击尺寸与比例读数。
- 未完成草稿保护、等待确认锁定、回执丢失与同一操作重试。

- 原有同批图片手势、复制失败、标注导出、分享、手机尺寸调整/扩图、后台结果不抢图和草稿保留。

- `numbered-feedback.mp4` / `.webm`：真实浏览器操作、选择和刷新恢复的短录屏。
- `draft-1440.png`、`draft-320.png`：重开及刷新后的编辑草稿。
- `zoomed.png`：200% 视图下固定大小的编号和一致的比例读数。
- `zoom-readout-before/`、`editor-focus-before/`：视觉检查发现的问题在修复前的失败截图与上下文。

服装图片是已有测试素材，任务结果由本地夹具提供。以上画面证明交互与恢复，不证明“收窄袖口”等模型生成质量。

## 发布与仍待验收的部分

共享请求中的 `imageEdit.markers` 是可选字段；旧请求不携带标记仍可处理。前端、API、Worker 和共享构建产物需要协调发布才能在实际任务中呈现编号参考。此次只保留本地改动，没有提交、推送、部署或运行生产 Worker。

本轮没有新增数据库迁移、模型调用、付费请求、后台轮询或持续动画。没有重新测量 100 对象白板帧率，不将历史性能数据作为本轮新结论。手机检查为 Chromium 窄视口及模拟触点，尚非实体手机验收。

位置标记表达的是用户指定的点，不等同于识别图片中的语义元素。自动拆层、元素移动、图片内文字识别与排版保留仍是独立能力；意见修改也不具备局部重绘蒙版路线的确定性选区外像素保护。真实模型对编号、多条意见、面料和版型保持的效果需要单独验证。
