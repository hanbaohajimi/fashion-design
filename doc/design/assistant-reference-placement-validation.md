# 聊天参考预览与明确放置

日期：2026-11-10。承接[聊天图片上传](assistant-image-uploads-validation.md)，将“加入聊天参考”和“放入画布”分开。上一阶段上传直接产生摆放；本阶段开始，新的聊天上传只增加项目参考，用户从预览中明确放置后才增加白板对象。视觉继续使用森织暖白、深绿和毛绒织芽。

## 用户操作

- 多选、粘贴或拖入聊天图片，继续走现有私有上传、处理和当前草稿引用。完成后不会自动摆到白板，也不改变视野、选择和其他对象位置。
- 点击参考缩略图或名称打开专门的只读预览，使用原有图片查看器，完整显示图片，保留滚轮缩放、拖动、双击、适合窗口、原始大小和加载失败重试。无需先放置即可看清参考细节。
- 发送消息后，可以从回复的引用记录再次打开同一参考预览，已有历史仍使用真实节点身份。不是只有未发送附件能预览。
- 在预览点击“放入画布”才摆放；先保存当前白板，在当前视野附近寻找空位，不移动其他作品。放置后提供“在画布中查看”，手机返回白板，桌面停靠聊天继续保留。
- 已有摆放只显示查看入口，同次浏览不重复创建；服务端也核对有效摆放。手动删除后可以再次明确放置，但刷新不自动复活已删除摆放。
- 预览打开、关闭和放置都不发送聊天消息或提交生成任务。关闭后正文、光标、引用和聊天实例保持，键盘焦点回到原引用。只读项目保留预览，隐藏放置操作。
- 画布工具和空白白板中的“上传参考图”仍是摆放素材的明确入口，维持原行为。上一阶段已经放在白板上的聊天图片不主动移走。

## 数据与恢复

`import_reference_image` 增加可选 `placement: "reference"`。省略时兼容旧命令，仍按原规则创建摆放；新聊天命令显式使用该值，不附加位置。新参考记录带 `canvasPlacement: "manual"`，不创建白板绑定。画布读取补齐和初始化都跳过这种尚未明确摆放的素材，防止刷新、切换项目或首次迁移时把参考自动摆回去。

`place_reference_image` 命令接收节点 ID、操作编号和可选位置。复用现有项目权限、私有文件、画布事务锁和幂等回执，核验来源属于项目、为真实参考图、文件已就绪且原图存在。已有有效绑定时返回原节点与摆放，不改变位置；需要重新放置时创建新绑定，保留已删除绑定的历史。不能用客户端图片地址、名称或尺寸伪造来源。无需数据库迁移。

项目生成文件和聊天参考共用 `useImagePlacement` 的持久化规则，原 `useGeneratedFilePlacement` 保留兼容入口和原存储键。新参考以账号、项目、编辑器和参考节点隔离放置记录；命令完整落盘后才发请求，直到返回画布成功应用并完成保存检查才清除。重复点击共用在途操作，两个窗口保存冲突保留先到回执。未知响应在关闭/刷新后只提示继续，使用原编号和位置；明确权限或参数拒绝允许核对后重新发起。关闭或账号/项目切换取消读取，迟到结果不应用到其他界面；不声称取消了已经提交的服务端事务。

参考图仍是项目素材，项目成员可按既有权限访问；“只在聊天中引用”不等于私密于某一段会话或未保存的本机文件。文件、项目和对话原有权限保持。正式缩略图后台的可选视觉摘要也继续沿用，不能声称上传绝不触发识别。

## 画面与性能证据

生成物位于 `output/playwright/assistant-reference-placement/`：

- `attached-*`：只有聊天参考的状态；`preview-*`：完整预览；`retry-*`：放置续办；`placed-*`：确认后状态；`canvas-*`：明确放回白板。
- `tour-1440.webm`、`tour-320.webm`：实际浏览器录屏。
- `clip-1440.json`、`clip-320.json`：四态裁切回执。范围为参考预览后代，不含dialog根容器自身投影；根容器另核对视口边界，不扩大审计结论。
- 展示使用仓库已有 `coat-original.png`，读取实际 PNG 尺寸并上传该文件作为夹具，缩略图使用同一素材。没有新生图，也没有用1px行为夹具的尺寸冒充最终摆放大小。320px启用触控模拟、减弱动态和系统暗色偏好，平台仍是现行浅色主题。
- `performance.json`：本轮100对象独立三段测量原始数据，结果见下表。
