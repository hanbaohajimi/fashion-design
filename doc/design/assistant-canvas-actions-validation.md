# 设计助手的画布工具

更新：2026-11-15。接续当前统一创作画布，保留现有工具栏、助手样式及生成流程。

## 能力与使用

| 能力 | 可以直接发给助手的例子 | 实际效果 |
| --- | --- | --- |
| 创建色卡 | 创建一张深绿、亚麻和暖白的三色色卡 | 新增具名色卡，支持1–12色 |
| 更新色卡 | 把选中色卡的第二种颜色改为酒红 | 提交完整新配色，沿用现有素材历史机制 |
| 添加面料 | 把面料库中的某款亚麻添加到画布 | 只使用当前账号可访问且图片就绪的已有面料 |
| 移动 | 把选中图片向右移动100 | 实际页面坐标位移 |
| 显示缩放 | 将这张图片缩小到300×400的显示范围 | 默认等比，保持原始文件不变 |
| 对齐与分布 | 将这三张图片顶部对齐；将这三张图片水平等距分布 | 分别调用原生对齐和分布 |
| 组合与解组 | 将选中的两张图组合；取消这个组合 | 保留原素材、输入及子对象 |
| 层级 | 将选中图片置顶 | 置顶、置底、向前或向后一层 |
| 打开界面 | 打开面料库；打开全部功能；打开裁剪图片 | 原有面板实际可见后确认，不自动处理图片 |
| 添加连接 | 把上游探索连接到下游夹克作为输入 | 追加真实素材或创作目标，可连接空目标 |
| 移除连接 | 断开下游夹克中的上游探索引用 | 使用目标真实输入编号，保留其他输入与要求 |

一次返回一个明确动作。目标名称重复、超出已读取对象范围、面料名称无法唯一识别、画布尚未就绪或请求不明确时，助手需要澄清。自动化验证使用确定的模型输出夹具，不保证真实供应商对每种自然语言说法的理解质量。

排版请求最多64个直接目标；包含组合后代时单次最多128个对象。当前观察优先读取选中对象和视野内对象，最多200个，明确记录未读数量；面料清单提供最近50项可访问资料及是否还有更多，未读项不能捏造ID。画布选择不自动改变显式聊天引用；需要读取图像内容时仍沿用实际图片补读机制。

## 执行与回执

1. 发送前同步当前创作要求、引用及白板，捕获对象ID、实际选择、父级、坐标、尺寸和稳定签名。
2. 服务端按持久化文档核实对象，读取目标当前输入、版本和可访问面料，向模型提供独立动作说明及参数schema。
3. 模型输出 `kind=canvas`、单一 `canvasAction` 和逐字完整用户指令；不能同时请求设计工具执行或图片生成。讨论、假设、否定和后台观察不授权自动操作。
4. 原消息先保存为待应用，由发起浏览器领取。排版串行执行，失败时回滚尚未保存的局部排版；素材和连接复用已有业务事务及稳定mutation ID，提交前重新校验意图、权限和版本。
5. 完成后保存画布，待色卡等对象自动尺寸稳定，再采集当前证据。服务端核对实际保存的对象、素材绑定或目标输入，更新原消息的完成文字；打开面板由浏览器确认实际可见。

模型的画布动作正文不直接作为流式“已完成”文字展示。完成反馈由核实后的业务事实产生，包含素材名称、对象数量或连接目标，不额外调用语言模型。

动作按账号、项目和发起浏览器隔离。页面刷新、会话历史及旧消息轮询不会自动执行历史动作；未知回执通过原消息的“继续确认画布操作”补核对。已经应用的排版保留操作后签名与保存阶段，恢复时不再次移动、缩放或组合；对象随后已有新修改时拒绝重放旧操作。存储不可用仍可使用当前页面内存状态，刷新后不能代另一客户端领取旧动作。

连接只修改目标草稿的输入；版本冲突、未保存要求、待确认保存、锁定、隐藏、循环、自连、超过16项及不支持的视频输入均被拒绝。修改色卡沿用已有被消费素材的派生规则，保留旧素材与历史。面料记录须属于当前账号或预设，图片已就绪；不创建面料事实或发起生成。

连接回执同时同步已打开的创作草稿及恢复基线，不能只刷新服务端记录。回填按连接前快照合并输入增删，保留后续文字及其他引用；合并超过16项时保留本机草稿并提示核对。已提交但响应丢失的连接以服务端mutation回执恢复，不把目标已增加的版本误判成另一项新操作。发送回执未知时冻结原画布观察，平移和自动尺寸变化不会让同一请求生成新编号。

手机打开功能面板时返回画布，聊天继续挂载。普通桌面开面板复用现有界面；底部入口、常驻图标和原有手工操作不变。

部分工作台沿用原流程准备空创作目标；助手为同一次打开使用固定目标与mutation编号，刷新恢复不能重复创建空目标，生成仍需原界面的明确执行。

## 验证证据

本轮日志与截图统一写入忽略的 `output/assistant-canvas-actions/`；浏览器失败调试产物位于 `output/playwright/`，不提交。

- 共享包构建，Web/API类型检查，目标文件ESLint。
- API单元测试覆盖独立工具说明、真实画布上下文、完整指令核对、讨论/否定、锁定父组、参数边界，以及与生图互斥；现有规划器与协调器一起回归。
- 真实PostgreSQL集成覆盖助手发送到待应用、模型抢先完成文字屏蔽、重复发送、领取、素材幂等、保存后确认、迟到失败不覆盖成功、私有面料授权、资料变更、只读权限、旧意图、目标新草稿、空目标连接和循环保护；同步回归既有直接生图与历史记录。
- 单worker Chromium在隔离API夹具上使用真实tldraw编辑器，核对移动、缩放、对齐、分布、层级、组合、解组的实际保存结果；覆盖回执丢失后刷新继续、创建/更新多色色卡、已有面料、空目标连接与移除、只读失败、桌面功能面板与390px手机打开面板，并回归现有草稿同步。

本地检查结果：API四个定向测试文件49项通过，Web两个定向测试文件13项通过，真实数据库21项通过，合计83项Vitest；两组单worker浏览器用例共16项。共享包构建、Web/API类型检查通过。目标lint为0错误，`CanvasModuleWorkspace` 既有私有图片预览保留1条Next Image优化提示；不为本次属性标记修改预览实现。最终日志分别为 `unit.log`、`web-unit.log`、`integration.log`、`browser.log`、`api-types.log`、`web-types.log` 和 `lint.log`。截图包含实际排版、390px全部功能、面料库、画布对象、裁剪输入及换色工作台。
