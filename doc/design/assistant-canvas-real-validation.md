# 设计助手真实模型与消息简化验证

更新：2026-11-15。接续[画布工具接入验证](assistant-canvas-actions-validation.md)，本阶段由用户明确授权调用真实模型，并追加要求移除消息下方“查看引用记录”。

## 实测范围

使用本机配置的 `anthropic/claude-sonnet-4-6`，经真实 Amux 网关调用；使用独立账号、项目和会话，导入三张已有服装图片，并准备“上游探索”和“下游夹克”两个空图片目标。认证、业务API、PostgreSQL、私有MinIO和tldraw编辑器均实际执行。模型返回和四项业务API没有响应夹具。

测试入口为本地4400端口：网页转发当前未改版的3000端口前端，业务API转发4401端口的真实应用实例。该实例仅为禁止图片生成，在执行入口设置拦截并记录尝试次数；四项画布动作和模型协议保持原实现。模型过程使用真实流式请求，输入图片从私有存储实际读取。密钥、认证Cookie和邮件登录凭证不写入证据文件。

整个测试项目的图片生成任务数、工作流执行数和被拦截的生成尝试数均为0。已有图片只作为导入素材与视觉输入，没有调用图片模型。

## 实测发现及修复

最初“做张色卡”和“把面料库调出来”均被执行校验拒绝。真实模型已经输出正确的 `create_swatch`／`open_panel` 动作，问题发生在 `allowsAssistantCanvasAction`：该校验依赖“创建”“打开”等有限词语，未接受口语表达。

现在支持明确请求中的“做张／制作／需要色卡”，以及“调出／展开／唤起面板”和指向确切界面名称的“看看”。保留完整原文核对、工具范围、对象身份、权限、版本、否定及假设保护；“昨天做过色卡”“别帮我做色卡”“假如做张色卡”等不能因此变成可执行操作。没有放开任意画布命令或图片生成。

修复前两项共调用四次规划模型（各含一次受限纠正）；修复后四项共调用四次规划模型，均直接完成。上述数字仅统计本次会话的规划调用。

## 消息下方的引用记录展示

按用户截图要求，`WorkflowAssistantPanel` 不再挂载消息中的 `MessageReferenceRecord`：移除“查看引用记录”折叠行及“这条回复未保存引用记录”占位。输入框编号引用、上传预览、当前草稿、结果操作及服务端引用元数据继续保留。

在真实测试页面刷新后，两种展示的数量均为0；六条回复的 `referenceSummary` 仍可从实际会话API读取，连线仍为一条，且没有前端页面异常。截图见 `output/assistant-canvas-real/reference-record-removed.png`。
