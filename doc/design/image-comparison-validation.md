# 图片比较与版本恢复验证

日期：2026-11-09，北京时间。本轮接续图片方向编辑，完善“比较多个结果—选中一版—继续修改—查看与恢复历史”的路径。既有导航精简与织芽方案保留，未重做形象、聊天或任务查询。

## 实现

- 图片工作区的同批缩略图旁增加“比较方案”；图像菜单也可进入。桌面并排完整展示当前图与对比图，缩放同时应用，放大后可分别拖动查看。三张及以上结果可切换对比对象。
- 小屏每次完整展示一张图，通过“当前图／对比图”切换，避免把服装挤进两个窄列。比较时隐藏外层重复缩放、缩略图和编辑工具；退出恢复，Escape 返回入口焦点。
- “继续编辑对比图”打开该资产的现有图片工作区；原图的方向草稿、标注和评论所属会话继续保留。比较本身没有恢复、生成或保存请求。
- 版本历史新增“对比当前版本”，明确当前与历史来源；恢复仍创建新版本。`transform` 历史名称更新为“图片调整”，覆盖原有裁剪/尺寸与新方向操作。
- 恢复前在既有 IndexedDB 草稿仓库保存当前资产、目标资产、固定的来源节点和两个操作编号，按账号、项目、编辑器及当前图隔离；不持久化图片或签名地址。创建资产和加入工作流的任一步响应丢失，都沿用原编号与来源重试，不重新挑选来源节点。
- 刷新只读取待续办记录，不自动重发。连续点击共享在途操作；另一页面有未完成恢复时，显示原操作。请求期间切换账号会停止后续接入，原记录保留供回原账号继续。
- 接入完成后使用返回的工作流更新画布并直接打开恢复产物，后续修改绑定恢复产物，不再停在旧图。
- 草稿仓库的条件删除新增可选内容匹配。记录删除后重新建立可能具有相同修订号；恢复操作同时匹配编号，较早的迟到成功响应不会删除下一项恢复。

本轮没有新增后台接口、数据库迁移、模型请求或轮询。恢复复用既有版本接口和工作流接入的幂等规则。

## 验证

定向单元测试 **3 个文件、20 项通过**，包含 8 项恢复行为、5 项草稿仓库事务及 7 项已有草稿生命周期测试。覆盖发送前落盘、两个步骤的响应丢失、重复点击、账号/页面隔离、存储失败、账号切换中止后续操作及迟到响应清理。

Chromium 浏览器 **20 个不同用例通过，单 worker**：

| 测试文件                    | 数量 | 本轮覆盖                                                                                                                               |
| --------------------------- | ---: | -------------------------------------------------------------------------------------------------------------------------------------- |
| `image-comparison.spec.ts`  |    9 | 1440/390/320px 比较与继续修改，历史分页/对比/恢复，两个步骤丢失响应后刷新重试，失败重读，多方案与方向草稿保留，320×640短屏与Escape焦点 |
| `image-orientation.spec.ts` |    6 | 原有旋转/翻转预览、新图片、草稿、未确认提交与短屏键盘回归                                                                              |
| `image-workspace.spec.ts`   |    5 | 原有图片手势、缩放、标注、评论、分享、尺寸、扩图参数与编辑期间新结果回归                                                               |

修正条件清除与账号切换边界后，5 项历史/恢复浏览器用例再次验证；重复运行和录屏不增加不同用例总数。Web TypeScript 与目标文件 ESLint 通过。根目录 ESLint 的既有 Pages 路径提示保留，不属于检查失败。

## 画面与边界

本机生成物放在忽略目录 `output/playwright/image-comparison/`：

- `compare-1440.png`、`compare-390.png`、`compare-320.png`：实际浏览器比较界面。
- `history-comparison.png`、`history-320-short.png`：历史对比与短屏操作。
- `image-comparison-tour.mp4`、`tour-1440px.webm`：比较、选中另一图、继续旋转与提交的真实操作录屏，正常播放速度。

服装图片复用仓库既有模型验证输出的原型副本（来源见 `apps/web/public/prototype-assets/impeccable/SOURCE.md`），测试中仅等比缩放和补白。未重新生成图片；项目、版本和任务由受控接口提供。第三张对照测试复用原图，只验证多选行为，不代表第三份设计产物。

此次恢复测试刻意模拟“服务器已完成，但响应丢失”，验证客户端重复请求的编号、产物选择和后续修改来源。没有以这些测试代替真实数据库、工作流事务或存储验证；本机 API/Docker 的已知故障边界仍见[上一轮记录](image-orientation-validation.md)。本轮未再次启动或重置 Docker。

320/390px 是浏览器视口模拟；深色系统偏好和减弱动态已覆盖，但平台仍使用既有固定浅色主题。没有新增独立深色皮肤，也没有宣称实体手机实测。本轮比较主要为静态工作面，未新增帧率结论，上一轮 100 对象旋转测量不自动算作比较性能。

公开检索本轮未取得可引用的新内容；沿用[能力对照](lovart-capability-review.md)中已留存的 Lovart 官方公开入口证据。没有验证其登录后比较或历史机制，本轮实现依据本平台现有来源链路和实际操作缺口。

未调用付费服务，未运行全仓检查或 CI，未提交、推送或部署。整体产品目标继续进行。
