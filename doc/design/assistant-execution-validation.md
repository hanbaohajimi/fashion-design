# 聊天执行进度与历史确认归属

日期：2026-11-10。承接[聊天结果回看](assistant-results-validation.md)，补齐排队、实际执行、停止后核对与历史确认内容的准确归属。继续沿用暖白、深绿、织芽和同一份设计聊天，不引入新的助手或任务调度。

## 行为

- 已提交的执行在原消息中显示真实进度：准备、排队、处理中、核对结果，以及明确终态。数量只来自对应执行的实际尝试与生成任务，显示已完成、排队、处理中、未完成、取消的项数；不推断队列位置、预计时间或百分比。
- 生成任务返回成功但工作流尚未核验并接入产物时，显示“正在核对任务结果”，不提前把任务计为已完成，也不退回准备执行。图片变换仍缺少实际处理开始信号时保持准备状态；已有分析尝试运行时显示处理中。
- 有当前项目编辑权限时，可以明确停止目前已排队或正在执行的图片任务。按钮标明“停止 N 项图片任务”，范围是此刻已有任务，不能被理解为取消尚未提交的准备步骤。沿用现有生成任务取消接口，已完成结果保留；不承诺撤回已经到供应商的处理或返还费用。
- 停止请求返回后先显示“已请求停止，正在核对执行结果”，刷新现有消息和项目任务查询，只有实际终态更新后才显示取消或部分未完成。部分停止失败明确提示，可重新读取；网络读取失败保留此前状态，不推断业务失败、不自动提交新生成。
- “查看任务详情”打开当前项目已有任务中心，不跳走或重建聊天。只读和归档不提供停止/重试；共享项目编辑成员遵循项目编辑权限，可以停止关联的项目任务，不能用计费归属账号不一致误拦操作。
- 正文、光标、输入实例和旧消息阅读位置在进度更新时保持。排队与运行切换、数量变化不误报新结果；只有关联到该消息的新终态或新消息才提示。旧页或迟到轮询不能把已经观察到的终态退回执行中，也不能恢复已失效确认的执行按钮。

## 历史确认内容与执行

此前 `ProposalReview` 使用工具节点今天的参数、状态和全部连线输出；后来的版本或重试可能影响旧卡片。本轮修正为：

- 确认时把接受后的真实工具版本ID写入原提案的evidence，同一事务提交；原提案中的参数、保留项和数量仍来自当时确认内容。当前工具参数不作为历史内容的替代。
- 从确认卡执行时附带proposalId，服务端核验项目、操作者、会话、接受状态、工具节点和已确认版本。输入已有后续变更时拒绝借旧确认执行。原请求回执重复提交继续幂等，未附带proposalId的既有入口保持兼容。
- 每次新执行快照记下明确关联的proposalId。消息读取按项目、会话、操作者批量读取实际执行和尝试；同一确认的显式重试可以显示其最新关联执行，原失败执行和原事实回执保持独立，不混成一个成功批次。
- 旧确认先用当时的提案变更记录和工具版本恢复接受版本；首次旧执行只有在请求编号与原确认的确定性编号一致时才关联。无法核实的其他旧执行显示“历史执行未核实”，不取同一工具的任意最新任务、不借当前成功状态构造历史结果。
- 确认后的版本改变时保留历史进度和结果，并说明需发送新需求继续；原执行仍可以正常收到后续终态。当前版本若已有无关执行，也不能把旧确认描述成尚未开始或启用继续执行。
- 关联到该确认的结果沿用上一阶段真实资产摘要及图片画廊，不从当前连线猜测。若同次事实回执已经在当前消息页呈现图片，旧卡片只给“查看本次结果”，定位并聚焦该画廊，避免重复图片。只加载旧卡而结果回执不在当前页时，卡片自身保留本次结果入口。

上述元数据使用现有提案evidence和执行requestSnapshot，不新增任务状态副本、轮询或数据库迁移。shared、API与Web需一同发布。旧请求缺少新关联时降级为可阅读的未核实记录；后端仍是最终权限边界。

## 实现与生命周期

共享 `WorkflowExecutionProgress` 和 `WorkflowProposalExecution` 提供只读观察。读取按当前消息页批量获取，区分执行、尝试和真实生成任务；项目权限、会话归属、历史版本与结果身份分别核对。读取不回写历史消息，不因为浏览启动模型或重试任务。

前端 `AssistantExecutionStatus` 复用 `TaskFeedback` 和原任务中心。暂停请求绑定当前执行，关闭、卸载或切换时中止请求并忽略迟到响应。`useSerialPolling.retry` 改成稳定回调，避免输入与周期刷新反复重建整段聊天；轮询仍用原2.5秒串行、页面后台暂停和失败退避。停止完成后复用原查询刷新，不额外起定时器。

白板继续按原节奏读取文档与权限，但在文档、素材、权限和待定位内容均未变化时跳过重复的对象投影。恢复本机草稿会清除该缓存，真实图片版本更新、权限撤销和恢复仍同步到白板。旧格式或损坏的执行/结果摘要经过结构校验后降级为可读消息，不产生虚构图片，也不中断其余聊天。

确认的内容默认折叠回看，状态、操作数量和当前可用动作在原卡片中显示。手机保留44px触控目标。没有真实引用记录的提交/确认消息不再增加“未保存引用记录”常驻文字；有已记录引用依据时仍可查看。

## 画面与性能

证据目录 `output/playwright/assistant-execution/`：

- `tour-1440.webm`、`tour-320.webm`：实际浏览器短录屏，无新执行或停止请求；使用仓库已有原型图片。

- `performance.json`：本轮独立状态更新/输入/平移的测量结果，只有取得实际回执后才列为通过。

独立测量初始100个素材对象和同一停靠聊天，原生时钟/rAF、每段30秒、单worker、无trace/录屏/并行检查。受控接口每2.8秒在排队/执行间切换，浏览器沿用原2.5秒串行消息刷新；分别测输入、工作时平移及完成后的平移。不以模型、生产网络或真实后台负载作结论，事件至下一次rAF不是显示器端到端延迟。
