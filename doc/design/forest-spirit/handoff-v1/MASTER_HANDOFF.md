# 01 · 外观锁定与视觉优先级

## 一、唯一角色基准

`references/00_approved_board.png` 是用户在本轮明确选定的形象，原图为 1254×1254。所有裁图保留原像素，不重绘、不锐化、不重采样、不重新调色。

视觉优先级：用户明确的“无睫毛”等约束 > 母图左侧主角色 > 从主角色裁出的细节 > 同一板中的小视图与表情 > 之前提供的工具袋及平台 Logo 辅助素材。

这不是新一轮角色概念设计。即使旧讨论曾建议换帽子、换发色或做种子角色，这一轮都以用户最新选择为准。

## 二、逐项外观锁定

| 部位 | 必须保留 | 禁止漂移 |
|---|---|---|
| 脸 | 圆润布偶脸，奶油米色织物纹理，安静神态 | 长尖下巴、塑料脸、真人皮肤、过度幼化或成人化 |
| 眼睛 | 棕色竖向椭圆的刺绣眼睛 | 绿色眼睛、大眼白、玻璃高光、眼线、睫毛 |
| 闭眼 | 一条干净弧形绣线 | 闭眼弧线旁的睫毛分叉、额外短线 |
| 嘴与鼻 | 母图的小型绣线或短折线，默认中性安静 | 永久咧嘴笑、涂口红、牙齿、夸张惊讶 |
| 头发 | 浅金/亚麻金发束，微卷与发辫细节 | 红色长发、绿发、突然变为一整块光滑头盔 |
| 帽子 | 米白宽檐软帽、暖红内衬、花叶浆果、铃铛 | 擅换叶冠、蘑菇帽或初始参考照片的造型 |
| 服装 | 米白植物刺绣披肩、橄榄绿衣片、陶红围巾/格纹、花边 | 大面积紫裙、荧光配色、额外盔甲或翅膀 |
| 脚部 | 米白罗纹袜筒、棕色短靴、翻边和木扣细节 | 裸露布脚、粉红脚尖、兔脚、细高跟 |
| 工具袋 | 棕色软皮/厚布袋，明显缝线，金色剪刀，纸样/材料卷 | 删除工具袋、在无关位置新加巨大工具 |
| 质感 | 布料、毛毡、纱线、木头与少量黄铜 | 扁平 SVG 替身、亮塑料或过强金属反光 |

“无睫毛”覆盖所有表情。保留母图原有的短细眉，不把眉毛误当成睫毛一并删除。概念板右侧闭眼小图若残留短线，不得照搬。保留其他面部特征，不因去睫毛重画一张完全不同的脸。

## 三、角度、左右与比例

主角色是轻微三分之四视角，不是完全正面的工程立绘。精确复现优先采用接近此角度的站姿主模型，只做小范围头身变形。若必须改成正面，先输出单张生产基准图供核对，不能暗中改脸。

“工具袋在右边”等描述统一使用**观察者在基准正视图中看到的方向**说明；程序的 L/R 参数则使用角色自身左右，二者不可混用。原图工具袋位于观察者右侧；不要为修正一处配件而整体镜像角色。

大图主角色、前视小图和其他视图存在生成插画常见的结构差别。它们只说明同一设计方向，不能把每个视图同时当作绝对几何真值。冲突时保持主图身份特征，再记录需要确认的结构。

## 四、背景与光照

森林、苔藓地面、纸纹板、色卡和标志不属于角色。最终运行纹理背景透明；软落地阴影应独立可开关。

保留柔暖的材料感觉，但避免把强烈背景光晕和深森林投影烘焙成角色边缘。浅色与深色工作台上都应检查边缘是否发白、发黑。

## 五、色彩

`specs/palette.samples.json` 是从母图色卡中取中央像素中位值得到的参考。它不是角色所有布料的准确底色，不能用这些纯色对角色整块填色。

色卡里有灰紫不代表应该把现有裙子改紫。材质与真实配色以母图左侧主角色为准。

## 六、品牌与权利

`26_platform_logo_original.png` 是用户先前提供的品牌参考；概念板中的标志只属于展示板，不是已批准的新 Logo。不得自动替换产品正式标志。

本包不包括用户声明禁止商用的最初娃娃图片。当前候选形象是否适合商业发布仍需独立的角色及许可审查；本包不构成无侵权保证，也不把重新生成当作权利已自动清理。

# 02 · 生产立绘、拆层与补画

## 先理解现有素材

现有的是一张压平的概念板。角色主图约为数百像素宽，正侧背小图仅约两百像素高。它能说明外观，但不是高分辨率生产原画，也不包含被遮住的区域。把图放大到 4K 不会自动恢复真实细节。

所有 `references/` 裁图都有原图坐标和哈希，见 `specs/reference_manifest.json`。它们用于比对，不直接放入最终纹理图集。

## 生产主立绘建议

建议先制作一张约 3072×4096 的透明底立绘，保留完整帽子、铃铛、鞋靴和周围动作余量。这是新生产资产建议尺寸，不是原图真实分辨率；根据实际显示与模型预算可调整。

优先保留主图轻微三分之四的身份感，手臂与披肩边界清楚，两脚完整可见。不得在这个步骤顺带重新设计。新增未见区域应遵循可见服装结构并单独审核。

站姿基准通过后再大规模拆层，避免先对错误外观投入绑定工作。

## 分层文件要求

建议交付：

- `forest_spirit_separation.psd`：保留编辑来源、遮罩和必要结构的美术母文件。
- `forest_spirit_import.psd`：适用于 Cubism 导入的整洁文件，每个可动部件一层。
- `layers/` 下可选的同画布透明 PNG 部件，便于审阅、版本控制和批量检查。
- `forest_spirit_master.png`：透明生产立绘合成图。

官方说明要求导入 PSD 使用 RGB、8 bit/channel，并建议 sRGB、唯一图层名、合并每个部件的相关效果与遮罩。[S1]

不要把一个扁平 PNG 包进只有一层的 PSD 后称为“拆层完成”。

## 拆层清单

完整建议清单在 `specs/layers.manifest.json`。组别包括后发、袜与靴、身体服装、双臂与手、围巾、面部、前发、帽子与铃铛、工具袋。

拆分依据是动作需求，不是越多越好。主花簇可以合并；每根纱线、每片小叶无需单独绑定。灵活合并不活动的层，但不能因此失去闭眼、扶帽或局部摆动能力。

可选的设计本、展开布片和提灯在 P2，第一版不强制制作。

## 必须补画的遮挡区域

- 面部去掉原始眼鼻嘴后，补齐完整织物脸；否则独立眼睛闭合时底层仍会留下睁眼。
- 帽檐抬起会露出的额头、发根与帽内衬。
- 头发摆动后露出的脸颊、耳侧、颈部与披肩。
- 扶帽手臂抬起后露出的袖内和躯干。
- 工具袋移动后露出的衣片；剪刀和纸卷在袋内的隐藏部分。
- 袜筒与靴口重叠部分，裙摆后方可能露出的腿部。

官方的素材处理教程明确提醒，应补画原图中被遮挡、运动时可能出现的部分。[S2]

## 遮挡与图层顺序

图层组列表不是最终绘制顺序。手触帽檐时，手必须能位于帽檐之前；围巾不能不合理穿过头发；工具袋前片必须挡住工具下部。需要分别安排前后部件、绘制顺序或必要的顺序关键形状。

工具剪刀默认保持刚性，工具袋摆动时不把金属剪刀拉弯。木纽扣同样避免跟布料一起大幅拉伸。

## 可验收的美术交付

重组所有层，应该得到与已批准生产立绘一致的合成图。输出：层列表、画布大小、实际左右定义、对齐方式、叠放顺序、需要动态顺序的部件、补画说明。

在白、浅绿、深绿三个背景上查看透明边缘；重点检查发丝、蕾丝、铃铛细绳、工具袋提带。不得留下森林背景碎片或明显白边。

# 03 · Cubism 绑定与动作规格

## 模型完成的定义

真正的模型需要网格、变形器、参数关键形状、纹理、动作与必要物理设置。仅存在若干参数名称或脚本不等于已经建好模型。

导出的 `.moc3` 承载实际运行模型；`.model3.json` 组织资源引用；纹理、动作和物理文件分别承担相应数据。官方导出流程由模型和动画工程生成这些资源。[S3]

## 参数

`specs/parameters.spec.json` 给出本项目建议。`ParamAngleX/Y/Z`、`ParamEyeLOpen/ROpen` 等使用官方标准命名；`ParamFS*` 是本项目自定义 ID，必须真实建立绑定后才有效。[S4]

头部角度数值只是模型参数，不应盲目当作真实空间角度。首版只制作小幅转头和抬头，避免布面、绣眼与帽檐过度拉伸。

棕色眼睛是简单绣眼，不增加眼球跟踪、瞳孔和眼白。闭眼用干净弧线，零睫毛；有必要时使用独立闭眼层和合理的透明度/形状过渡，不要用一块不匹配的肤色矩形盖住眼睛。

## 首版必做动作

| 动作 | 建议起始规格 | 要点 |
|---|---|---|
| Idle | 约 6 秒低幅循环，可叠加稀疏眨眼 | 固定位置，织纹不伸缩变形 |
| Hover | 约 1.8 秒，单次 | 轻抬头、扶帽檐、收手、回到安静 |
| DragHold | 约 0.3 秒进入并保持 | 被提起的轻微姿态，屏幕移动归网页 |
| PutDown | 约 0.55 秒，单次 | 站稳、微小余摆，无弹跳果冻感 |

这些是制作初值，不是已经交付的动作。详细节拍见 `specs/motions.spec.json`。

TaskReady、NeedsAttention 属于后续功能；设计本、布片、提灯等额外表演暂列 P2。

## 物理与材料

头发、帽尖、铃铛、围巾尾和裙摆做低幅阻尼运动。工具袋较重，摆幅应更小。足部与木扣保持相对稳定。无需持续环境风。

不要让动作曲线与物理系统同时不断写同一输出参数。先定义每个参数的负责模块，验证实际合成顺序；参考官方示例，不把几个更新函数随意叠加。

眨眼也只允许一个主控制来源：若 Hover 已记录眼睛关键帧，自动眨眼不能把它覆盖。表情恢复时不得停在惊讶或闭眼状态。

## 工程与运行资源

建议输出：

```text
forest_spirit.cmo3
forest_spirit.can3
runtime/
  forest_spirit.model3.json
  forest_spirit.moc3
  forest_spirit.physics3.json
  forest_spirit.cdi3.json              # 建议提供，便于调试
  textures/texture_00.png
  motions/idle.motion3.json
  motions/hover_greet.motion3.json
  motions/drag_hold.motion3.json
  motions/put_down.motion3.json
  expressions/...                     # 实际制作后再列出
```

命名是项目约定，可随导出工具调整，但引用必须一致，路径区分大小写。不要预先生成引用不存在文件的“正式模型”。

Editor 的目标版本、Core、Framework、示例版本须兼容，记录并固定。纹理先以一张 2048 级图集作为预算探索而非质量上限；若面部/花边不够清晰，评估 4096 或分图集并记录性能，不把任何尺寸写成普遍硬规定。

先在 Cubism 的实际预览中验收，再在 Web SDK 中测试所有状态、边缘、透明度和参数重置。仅编辑器可见不等于网页已可运行。

# 04 · 工作台网页接入

## 接入前核对实际仓库

本包不是项目源码审计。Codex 应先核对实际 React/Vite 或其他前端结构、白板实现、现有聊天面板、状态管理、项目/会话 ID 和测试框架；不要假定历史中的端口、路径或库版本仍然成立。

## 渲染架构

建议工作台独立浮层，Live2D Canvas 不进入 Fabric 等白板素材集合。白板坐标和屏幕浮层坐标分开；缩放、平移、框选、编组、连线、作品导出不应包含精灵。

模型播放器只处理资源与动作，交互层处理手势，业务桥接层调用现有聊天与任务。接口参考 `specs/runtime.contract.ts`，它是应用接口约定，不是 SDK 已实现的功能。

官方 Web 示例需要 Framework 与 Cubism Core；示例 GitHub 仓库不管理 Core，必须从官方 SDK 下载取得。[S5] 不要使用本包不存在的 Core，不要擅自从随机 CDN 拉取。

## 固定交互

用户确认：悬停一次回应、左键打开完整对话并隐藏角色、长按拖动、无自主游走、无小面板。

`specs/interaction.config.json` 给出可调初值：长按 400 ms，点击抖动阈值 6 CSS px，悬停冷却 1800 ms，显示高 220 CSS px。它们是建议，不是正式验收中的固定审美数值。

### 必须区分的状态

`idle -> hover_greet -> idle`

`pointer_down -> short_release -> chat_open_hidden`

`pointer_down -> long_press_armed -> dragging -> put_down -> idle`

`chat_open_hidden -> chat_close -> idle`

状态中还需覆盖 `loading / error / cancelled / disposed`，不能用一个布尔变量兼任按下、拖动和对话开关。

### 手势处理细节

- 只处理有效命中后的主指针与左键。右键不承担主要功能。
- `pointerenter` 触发回应，不把 `pointermove` 当作重新播放触发器。
- 短按松开且位移在阈值内，立即打开现有对话；不用等动画。
- 长按到时进入可拖动状态，本次点击被消耗，即使长按后没移动也不打开对话。
- 若长按前位移已经超过阈值，取消短按与长按候选；不能擅自退回“立即拖动”这个已被替换的方案。
- 拖动应使用可靠的 pointer capture，处理 pointerup、pointercancel、lostpointercapture、窗口失焦和组件卸载，及时清理定时器。
- 松手不再触发第二次 click；建议明确统一由 pointer 状态机决定业务动作。
- 回到精灵显示状态时，若鼠标正好停在原位置，避免恢复操作自身再次意外触发一轮动作。

## 命中区域与透明边缘

透明 WebGL Canvas 本身仍是 DOM 矩形，透明部分不会自动穿透鼠标。官方默认 HitArea 也不能等同于按每个透明像素精准命中。[S7]

建议大渲染浮层 `pointer-events:none`，另设紧贴角色主要轮廓的 SVG/DOM 交互区域，或实现经过验证的项目命中路由；检查发丝和铃铛的细小空隙不要制造大片阻挡。所选实现必须实测，不只在代码里写了 `hitTest` 就算穿透通过。

不要每次鼠标移动同步读取大幅 WebGL 像素造成卡顿。命中形状可取适当扩展的主体轮廓，不需要覆盖每根发丝；完整渲染边界和可点击核心范围可以不同。

## 位置与会话

位置在工作台可见区域的 CSS 像素坐标下计算。建议用“可移动余量”的归一化坐标保存，窗口变化或面板收起后重算并夹紧。定位范围不包括全局导航和输入区，具体边界以现有布局确认。

对话展开调用既有 store/service，不创建新 session，不清空输入草稿，不改变已提交任务所用素材。业务事件需带 `projectId`、`conversationId`、`taskId`，防止跨项目完成提示串入当前项目。

精灵隐藏只是视觉状态。任务继续执行，聊天继续接收结果。对话收起恢复角色和之前位置。

## 生命周期、性能与降级

建议可见时 30 FPS 起步，设备像素比最高 2 作为初始性能方案；这不是实测预算。记录真实帧时间、资源大小和峰值内存。

聊天展开或页面不可见时暂停角色更新与渲染；恢复时限制时间步长，避免物理猛跳。卸载时取消 RAF、计时器与监听、释放本实例资源；共享 Core/Framework 需集中管理，不由某个组件重复全局 dispose。检查 React StrictMode 重复初始化。

模型加载失败时保留现有助手入口；可用标注为 fallback 的静态角色，但不能当作 Live2D 成品。处理 context lost、资源 404、路径大小写、CORS 和组件加载竞态。不要在任务文本里泄露内部堆栈或访问令牌。

## 可访问性与触屏

精灵入口可键盘聚焦，Enter/Space 打开对话，提供清楚的 aria-label，必要的焦点轮廓不算“教学小面板”。遵循 prefers-reduced-motion 降低动画。触屏无 hover 时直接点击对话，长按移动仍可保留，且不干扰整个白板的双指操作。

## 主动建议的接口边界

可以接入真实任务完成/失败事件，但主动建议具体内容与频率尚未确认，第一版默认关闭主动策略。不要调用大模型分析每次鼠标移动，不自动录音，不自动新增付费生图。若只做预留接口，明确记录为预留，不声称已完成智能主动协作。

# 05 · 分阶段验收

## A. 资料包验收（本次可执行）

- 原图 SHA256 与 manifest 一致。
- 所有裁图边界有效，保持原像素，不重新缩放或调色。
- 资料包没有最初禁止商用的娃娃照片。
- 引用路径、文档和 JSON 均可读取。
- 缺失生产模型明确标为缺失，无伪造 `.moc3`。

运行 `python tools/check_handoff.py`。通过只证明本包完整，不代表模型已完成。

## B. 外观基准验收（待生产资产）

并排比较生产立绘与母图，重点逐项截图：

1. 面部、眼睛、嘴形和发色不变，所有表情零睫毛。
2. 棕色短靴、罗纹袜与工具袋可辨认，不回退裸布脚。
3. 帽子、围巾、披肩和配件布局保留，工具袋未被镜像到另一边。
4. 森林背景、苔藓地面、Logo、文字和色卡已排除。
5. 小尺寸预览 160 / 220 / 280 CSS px 高度均清楚；这是预览档位建议。
6. 白、浅绿、深绿背景上无明显白边、背景残渣或硬切割。

不能以机器像素差为唯一指标：生产角度、透明背景与受控补画会造成合理差异；关键是身份与材料保持一致，并有人工审阅。

## D. 交互自动化与人工场景

| 场景 | 预期 |
|---|---|
| 移入后静止 10 秒 | 只播一次 Hover，不循环 |
| 在身体内部移动鼠标 | 不重播 Hover |
| 快速重复进出 5 次 | 无动作排队，遵循冷却 |
| Hover 播放中短按 | 立即打开既有对话，精灵隐藏 |
| 短按轻微抖动 | 在阈值内仍正常打开对话 |
| 长按进入移动后松开 | 不打开对话 |
| 长按后拖出组件边界 | 仍连续拖动，最终位置合法 |
| 按下后长按前快速移开 | 取消候选，不误开对话、不变成立即拖动 |
| pointercancel / 窗口失焦 | 状态复位、无残留计时器 |
| 收起对话 | 精灵恢复旧位置，会话、草稿、任务不变 |
| 白板放大、平移、导出 | 角色尺寸与定位不被白板变换；作品中没有角色 |
| 点击精灵周围透明空白 | 白板素材仍可正常操作 |
| 切换项目后旧任务完成 | 不串到新项目对话或提示 |
| 打开对话/切后台标签页 | 渲染循环按策略暂停 |
| 卸载后重新进入 20 次 | 无重复监听、残留 RAF 或持续增长的模型实例 |
| 资源 404 / WebGL 故障 | 助手入口仍可用；明确 fallback |
| 键盘与 reduced motion | 仍能对话；动画减少，不失去核心功能 |

自动化测试对话开关、状态机和资源路径；透明命中、纹理质量与动作自然度需要实际浏览器和视觉检查。
