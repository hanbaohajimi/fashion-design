# 06 · 已有与缺失资产

## 已有，本次交付

- 最后确认的概念板原文件及原像素裁图。
- 平台 Logo 与工具袋辅助截图。
- 外观锁定、分层计划、参数计划、动作节拍和交互规范。
- 官方来源清单、接口约定、基础校验脚本。

## 缺失，必须继续制作

| 资产 | 为什么不能从现有板直接得到 | 下一步 |
|---|---|---|
| 透明站姿生产立绘 | 板有背景、遮挡与小尺寸细节 | 保持定稿身份制作并核对 |
| 部件补画 | 背景和前层遮住真实像素 | 补额头/发后/袖下/袋后/鞋口等 |
| 分层 PSD | PNG 已压平，没有层信息 | 按清单拆层、补画并验证重组 |
| `.cmo3` / `.can3` | 未制作网格、变形器、关键形状和动画 | 在实际 Cubism 工作流完成 |
| `.moc3` 与模型入口 | 未导出真实运行模型 | 用兼容目标导出并验证 |
| 纹理图集 | 裁图不是无背景生产纹理 | 从正式模型生成 |
| 动作与物理文件 | 规格仅描述动作，不是已绑定曲线 | 实际建模、调试和导出 |
| Web Core 与匹配框架 | 不在本包，许可独立 | 从官方来源取得并固定版本 |
| 当前仓库接入代码 | 本次未读取用户实际代码仓库 | 由 Codex 先审计再最小改动 |

## 工作分工

Codex 可以依据真实可用工具整理、检查和组装素材，开发网页集成、状态机和测试；美术重绘、遮挡补画和 Cubism 建模是否能自动完成，取决于实际工具与环境。不能仅凭语言要求假设这些能力已经存在。

若有图像编辑/建模自动化，要求先验证小范围动作和文件导出可用，再扩大；若没有，产出精确美术/建模交接，不把替代动画说成成品。

当前唯一需要继续确认的是新增生产资产是否忠实于已批准形象，而不是重复询问已经确定的交互和风格。
