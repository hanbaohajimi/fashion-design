# 画布图片完整性与导出恢复验收

日期：2026-11-10。继续优化作品在画布上的完整呈现与交付可靠性，保留森织暖白、深绿、材质外观与毛绒织芽。本记录是本轮定向证据，不是全平台与Lovart对等的声明。

## 已复现的问题

原无限白板把图片放进固定320×380的摆放，并使用cover铺满。1200×300的四色边缘测试图实际导出后，左右红蓝边缘像素为0。修复前文件保存在 `output/playwright/canvas-image-sizing/before/宽幅.png`；保留失败证据，不以通过检查替代问题复现。

## 当前行为

- 新图有有效宽高元数据时，在320×380范围内按原比例放置，小图片不自动放大。优先使用标准width/height字段，兼容完整的imageWidth/imageHeight字段对；无效或缺失元数据使用默认摆放框。
- 所有平台图片在摆放框内完整显示，不再通过cover自动裁边。旧摆放、手动缩放和版本更新保留原位置与外框，避免改动既有排版；缺失尺寸也能完整查看图片。
- 选中图片后可“匹配图片比例”，去掉留白，保持当前图像尺度与中心，支持撤销、重做和刷新恢复。旋转后的中心计算有单元验证。只读、锁定与祖先锁定仍限制布局编辑。
- 图片加载后缓存与当前地址关联的实际宽高，仅供本地摆放使用；不把旧地址的尺寸用于新版本。新增字段可选，旧格式快照可加载。只读转为可编辑后，已加载图片无需刷新即可使用匹配操作。
- 透明图片不再透出IMAGE/CDN占位说明；读取失败提供“重新加载图片”。重新加载保留位置和尺寸。图片标签保留最小12个画布世界像素的字号，防止宽幅、长图标签随面积变得过小；仍随画布视野缩放。

元数据更新不新增素材、不创建会话、不调用模型。只有用户明确调整摆放时，沿用原布局保存链路。极端图片的完整外框不等于手机上所有细节无需放大；仍可通过缩放和详情查看原图。

## 导出完整性

平台图片、面料图和流程图图片在导出前读取并实际解码。相同地址的多份摆放去重，每批最多4次读取，单次读取有20秒期限。HTTP失败或内容损坏给出带对象名称的提示，不下载缺图PNG；重试会重新读取，不延用上次失败。

校验通过的字节只交给导出副本，不重写真实画布地址或快照。导出预处理期间更换图片版本会要求重试，避免混用新旧图片；离开项目中止未完成读取，账号切换沿用已有私有请求生命周期。图形、便签和色卡继续使用原导出链路，隐藏内容沿用前一轮排除规则。

前一轮导出动画、编辑控件和便签原生输入框的修复继续保留。混合画布缩放前后文件一致的回归仍通过。原生tldraw图片会接受读取校验，其内部嵌图仍由tldraw完成；本轮实际像素证据覆盖平台自定义图片与流程图导出，不扩大到所有原生媒体和文件格式。

## 性能定位与快速保存修复

标签可读性调整后的独立100对象复测曾未达目标：目录关闭59.24fps、长帧0.506%，展开57.64fps、长帧1.792%。保留在 `performance-unmet-2026-11-10T021043.json`，不以更早的通过结果覆盖本次失败。

`frame-diagnostic.json`记录三种各10秒的诊断：原呈现、临时禁用低细节SVG阴影、临时取消材质内部强制图层。后两者均未恢复目标，没有把它们作为正式优化。CPU采样进一步定位到`CanvasObjectsPanel`在平移时被上层更新带动重绘；目录自身的字符串投影没有阻止这种父级渲染。

正式修改只为目录增加memo边界并稳定关闭回调，内部对象、选择、搜索和权限订阅继续生效。前后CPU证据分别为 `cpu-before-panel-memo.json` / `pan-before-panel-memo.cpuprofile` 与 `cpu-after-panel-memo.json` / `pan-after-panel-memo.cpuprofile`；目录不再出现在后一次的应用渲染热点中。诊断采样带有额外观察成本，不代替最终独立性能测量。

加快操作后，层级回归暴露了另一个时序问题：选择触发的保存可能早于700ms的草稿捕获，新服务端基线配上旧React草稿，导致刷新后把旧层级恢复并再次保存。已在保存确认时将当前编辑器快照与新基线配对，更新并持久化本机草稿，同时保留请求期间的新编辑。快速层级操作刷新、旧回执重放、保存中继续编辑、新增素材、丢失回执刷新及旧布局恢复均已通过相关用例。
