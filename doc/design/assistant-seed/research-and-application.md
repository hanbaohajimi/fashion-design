## 用户意图

保留第一版织芽，可适度美化。用户所说的「自然、真实」具体指：形象可以很简单，但反应像一个活着的小角色。此前纯绿色临时身体用于动作试验，不是用户选择的新形象。当前路线是非 Live2D 的轻量角色。

参考视频提供简单角色的表情、形变和短动作感觉；其中的语音、音乐、系统操作等宣传能力不自动变成本项目需求。此次轮廓、五官、叶片和动作代码独立绘制、编写，没有导入 DS 鲸鱼娘或研究产品的模型、纹理、动作文件。

## 造型修订

- 维持软圆外形，底部有接触地面的重量感；两片大小不同的叶子保留方向性。
- 默认面部保持安静。眼睛增大，嘴缩为轻弧线；笑眼、张嘴和淡腮红只在合适情境出现。
- 少量平整色块与底部明暗表达厚度，收掉高光描边和环绕装饰。
- 保留五官和叶片的轻微不对称，动作整体稳定，避免每层同时乱动。
- 主预览画布为 216 px，可切换到 96 px 入口画布。96 px 是完整图形画布，不是外壳净宽。

## 动作设计与实现

| 情境 | 表现 | 控制边界 |
| --- | --- | --- |
| 安静陪伴 | 偶尔眨眼，短暂瞥视，再安静；没有常驻浮动。 | 稳定后停止连续绘制，下一次事件到来再唤醒。 |
| 鼠标靠近 | 眼睛先看，面部与身体随后转向；指针停住后注意力自然回收。 | 被动跟随只用于精细指针，触屏关闭。 |
| 叫它一声 | 察觉、歪头、停一下、笑着点头、收住。 | 连续点击不重置招呼；忙碌中只做短暂回应。 |
| 思考 | 看向斜上方，稍偏头，间歇收回视线。 | 持续展示，不自动假装完成。 |
| 开始设计 | 低头关注工作方向，间歇抬眼，身体稳定。 | 不用旋转、假进度条和连续大动作假装工作。 |
| 任务完成 | 察觉、压缩、轻跳、落下缓冲，笑容逐渐收起。 | 演出约 1.75 秒；同一正在演出的状态不重复起跳。 |
| 需要确认 | 轻歪头看向用户，收敛到等待姿态。 | 正式版必须区分失败、取消、待确认的语义。 |
| 长按拖动 | 400 ms 提起，位置跟手，身体与叶片有惯性。 | 6 px 位移阈值、边缘约束、多指隔离、取消回起点。 |
| 松手 | 轻微压缩和恢复。 | 保留落点，新动作从当前姿态继续。 |
| 聊天显隐 | 打开时隐藏并停掉绘制，收起时恢复。 | 不补播隐藏期间的庆祝；样稿聊天仅为显隐示意。 |
| 减弱动态 | 稳定表情与状态文字。 | 关闭位移、倾斜、叶片摆动；短暂反馈仍按时结束。 |

调校初值：

- 目光与身体的启动差约 95 ms。响应速度不同，快速输入不会使身体瞬间跳到指针方向。
- 眨眼闭合约 55 ms，停留约 20 ms，睁开约 115 ms；间隔 3.2–7 秒。只控制必要变化，不把所有层分别随机化。
- 招呼约 1.45 秒；忙碌中的短回应约 0.85 秒。角色表演时长不等同按钮、面板交互响应时长。
- 完成动作预备约 0.32 秒再起跳，按阶段设定目标，避免每帧重复施加起跳冲量。
- 无指针互动时每 10–16 秒有一次约 0.9 秒的自主瞥视。明确选择安静陪伴后有安静时段。
- 眼睛在同一组曲线点间变形，不叠放两套眼睛淡入淡出；嘴使用连续曲线，避免单纯缩放嘴型。

这些是可调起点。是否自然仍需用户结合正常速度和真实大小判断。

## 实现路线与成本

本轮采用原创 SVG、原生浏览器事件和轻量弹簧控制，未安装动画库，也未为角色动作调用图像、视频或语言模型服务。动画本身没有新增云端推理请求；原有聊天和生成服务费用不在此结论范围。

Rive 是研究案例采用的工具，后续由专职动画设计师维护大量动作时可以评估。本轮借鉴其分层和状态驱动方式，当前简单形象先用现有 Web 技术落地。选择工具不能自动保证审美，现阶段投入重点应是轮廓、关键姿态、时序及真实交互下的打磨。

- 位移、倾斜、压缩与叶片各用独立层，避免争抢同一个变换。
- 物理积分限制步长；动作结束按真实经过时间判断，避免掉帧使表演明显变慢。
- 大部分部件使用变换；眼嘴小路径只在数值变化时写入。路径变化会引起局部重绘，不能宣称整套动画只走合成层。
- 稳定后取消逐帧调度；眨眼、瞥视、输入到来再唤醒。隐藏、失焦、聊天展开、不可见时暂停；卸载清理监听和观察器。
- 正式 React 组件用控制器或 ref 存放运动值，避免每帧触发工作台重新渲染。

## 验证与修正

独立 Chromium 样稿的检查：

- 完成中途切换设计，超过完成原定结束时刻后仍保持设计，旧动作不覆盖新任务。
- 设计中招呼结束仍保持设计；完整完成演出能回到陪伴。
- 长按提起、65 px / −16 px 拖动、松手落定、Escape 取消恢复起点。
- 设置回传后，55 px / −12 px 的位置保持，不被状态保存重置。
- Enter 打开对话后隐藏并暂停；对话中收到演示完成事件，恢复不补播。
- 减弱动态下完成时位移与倾斜为零、连续绘制关闭；完成和招呼按时退出。
- 320 px 内容宽度无横向溢出，情境按钮 44 px 高；96 px 入口和明暗主题已截图检查。
- 触屏模拟中精细指针查询为 false；触摸长按提起、20 px / −10 px 拖动、松手、轻点打开对话通过，未发现页面脚本错误。
- 安静时连续观察 700 ms，帧计数保持 4，确认该时段没有常驻动画循环。这不表示整页 CPU 为零。

修正：完成提示上移以避开叶片；设置回传仅在值变化时应用并保留位置；修复减弱动态下数毫秒的结束期限被忽略导致状态不退出的问题。

未修改应用源码，未运行全仓检查、构建或 CI。尚未验证真实工作台负载、真实任务服务、手机真机和长期运行；独立样稿流畅不等于生产 60 fps 已通过。

## 下一步接入计划

### 第一阶段：角色与旧模型加载解耦

当前 `ForestSpiritAssistant.tsx` 仍受旧开关控制，加载 `/live2d/forest-spirit/asset-manifest.json`；`spirit-contract.ts` 的就绪条件固定为旧角色、Cubism 资源和旧视觉约束，不能仅把 SVG 地址放入旧清单。

提取样稿的图形与运动控制器，建立独立的轻量呈现组件。复用现有手势层的长按、阈值、取消处理、账号 / 项目位置记忆，以及 `WorkflowCanvas.tsx` 的聊天开关和暂停条件。新入口应与旧资源是否齐备解耦。

交付判据：真实工作台可显示、拖动、打开 / 收起原有聊天；切项目和账号不串位置；明暗、手机、减弱动态正常。

### 第二阶段：真实任务驱动

现有 `SpiritTaskEvent` 仅声明 `completed | failed`，不能视为思考、运行、待确认已接通。由既有会话和任务数据生成展示状态，复用当前请求和订阅。

区分思考、运行、成功、失败、待确认、取消；按项目、会话、任务隔离，去重终态，历史恢复不庆祝，多任务合并提示。悬停和拖动不覆盖真实任务；失败不等同待确认，读取失败也不推断业务失败。

交付判据：真实状态映射正确；新任务开始后，旧回调不能拉回陪伴；角色只展示反馈，不自行发起生成或消费。

### 第三阶段：真实负载下收敛与验收

先稳定当前动作与打断、恢复，再按实际使用增加少量动作变体；同一性格、同一节奏，不靠堆道具和频繁随机动作补充存在感。

在代表性项目中测试图片加载、画布缩放、输入与多任务并行。记录设备、浏览器、刷新率、画布复杂度和时长，比较角色启用 / 关闭的差异。60 Hz 设备暂以平均帧率至少 58、超过 33.3 ms 的帧间隔少于 1% 为目标；这是待验收目标，本轮没有测得。

优先处理主线程占用、逐帧 React 更新和不必要绘制。如果实测仍不达标，再评估隔离绘制或 Rive。相关状态、手势测试、定向 lint、类型检查和单 worker 浏览器验证通过后，切换正式入口。
